# GraphQL authored evidence

`shop.graphql` is an original fixture covering SDL type families, directives,
defaults, OneOf, interfaces and schema/type extensions. `round-trip.graphql` and
`edited.graphql` are generated by `bun test tests/graphql`.

`scripts/graphql-oracle.py` uses pinned GraphQL-core 3.2.12 to check source/AST
retention, seven query comparisons, introspection, coercion and changed-default
execution. Results are in `oracle-results.json`. GraphQL-core is a GraphQL.js port:
this is independent runtime evidence, not unrelated implementation ancestry.
Custom scalar/directive behavior is not supplied or certified by these checks.

The adapter uses GraphQL.js 17.0.2 and its SDL AST declaration schema. Actual browser
checks are in `scripts/browser.ts`. The upstream corpus below expands preservation evidence; no cross-system projection
claim is made yet; see CONTRACT-009 for the exact profile.

## Pinned upstream corpus

`upstream/manifest.json` pins GraphQL.js v17.0.2 and SHA-256 hashes. Unchanged sources
and their MIT license are retained. Both benchmark GraphQL artifacts are included:
the GitHub schema is a complete model; the kitchen-sink operation is outside SDL.
The separately extracted kitchen-sink SDL is grammar-valid but not standalone.

`bun scripts/graphql-corpus.ts` extracts 48 static parser inputs and records six
dynamic exclusions in `parser-cases.json`; no upstream code is executed. Twenty-nine
syntax-valid fragments round-trip in explicit fragment mode and nineteen syntax
errors fail. All snippets fail complete-schema mode. `parser-corpus-results.json`
records outcomes. Python agrees with 47/48 grammar cases: directive extensions exceed
its profile. That exact disagreement is a regression gate.

`github-round-trip.graphql` and `schema-corpus-results.json` record exact preservation
of the 368,240-byte GitHub schema and 540 declarations. The Python corpus oracle
compares all introspection over 552 types and detects a changed output-type negative
control. `corpus-oracle-results.json` records evidence and limitations. Both corpus
steps run in `bun run test:conformance`; standalone commands require Bun tests first.

## Input document projection

`input-projection.graphql` is an original recursive input/OneOf/default fixture.
Bun tests emit `input-projection.json`. The Python projection oracle compares thirteen
native input-coercion and JSON-validation cases and checks three negative controls:
removing default insertion, singleton-list or ID coercion reports must fail accounting.
Versions and outcomes are in `input-projection-oracle-results.json`.

`input-projection-corpus.json` selects AddCommentInput, CreateIssueInput and
CreateProjectInput from the pinned 90-input GitHub fixture. Three examples are not
coverage of every input. Their nine positive/negative comparisons are recorded in
`input-projection-corpus-oracle.json`. Custom scalar mappings, GraphQL output/response
selection and actual runtime coercion remain outside this input-shape binding.
