# TypeSpec evidence

`project/` is an original authored multi-file model with namespaces, standard
decorators, templates, recursive models, enums, unions, interfaces/operations, comments,
Unicode and an unsafe-for-JavaScript numeric literal preserved as source text.

Bun tests round-trip exact sources through UMF JSON/YAML and compile with the pinned
1.16.0 compiler in a memory host. Changing an integer field to string while retaining
its numeric default causes a native semantic error. The emitted source bundle and
invalid edit are recorded in JSON fixture artifacts. `compiler-oracle-results.json`
records native CLI outcomes using a filesystem host; it shares the compiler code and
is explicitly separate-host evidence, not independent compiler agreement.

The standard library is bundled under `spec/extensions/typespec/` with MIT license
and a version/hash manifest, generated by `scripts/typespec-standard.ts`. Browser
evidence compiles a two-file bundle and rejects the semantic edit. Unknown metadata
retention, export refusal and unsupported imports have negative tests. Project
configuration, external libraries, type-graph representation and projections remain
unfinished and are not claimed by these source-preservation checks.


`semantic-graph.json` records selected compiled Order and Orders-interface views, with
recursive/inherited references, exact literals/defaults and source provenance. Tests
compare extraction before/after source YAML round trip and validate the complete result
schema. `semantic-oracle-results.json` records native filesystem-host inherited-property
traversal compared with graph-derived fields. Same-compiler limitations remain explicit;
this is consumer metadata evidence, not semantic-graph reimport or projection evidence.


The full upstream samples/specs subtree is pinned at commit
`5ee1157f337e461e50a7d57c2be2ae95e5026a4a`. Its 110 sample/context files include 51
TypeSpec files; license and compiler metadata bring the archive to 112 files. Hashes
and source paths are in `upstream/manifest.json`. Generated reference files and custom
code are retained as evidence, not silently imported or executed.

`corpus-results.json` records all 31 entrypoints. Thirty bundles preserve exact sources
and diagnostics through both JSON and YAML. Two compile (encoded names, string
templates); 28 report errors with unavailable libraries/context. The deliberately
invalid local editor example is rejected and retained in the archive. The separate
filesystem host agrees with all outcomes and diagnostic-code multisets for the 30
syntactically accepted bundles (`corpus-oracle-results.json`). Both hosts use TypeSpec
1.16.0. This is preservation and scoped compilation evidence, not full sample support.


`library-corpus-results.json` adds explicit HTTP 1.16.0, REST 0.86.0, OpenAPI 1.16.0
and Streams 0.86.0 selections. Twenty entrypoints compile, ten retain compiler errors
and the same intentionally invalid syntax fixture remains excluded from compilation.
Source/library selectors and diagnostics survive YAML round trips. The filesystem-host
comparison agrees on all thirty syntax-valid programs (`library-corpus-oracle-results.json`).
The original no-library baseline is retained separately. This is not emitter execution
or a claim that the ten remaining error cases are supported.


The all-library profile additionally selects GraphQL 0.3.0, JSON Schema/OpenAPI3 1.16.0
and Protobuf/Versioning/SSE/Events 0.86.0. Published library-root configuration is
archived and mounted; GraphQL's auto-decorator feature depends on this file. The profile
compiles 29 entrypoints; petstore's unregistered custom JS remains a compiler error and
the intentionally invalid editor fixture remains rejected. All thirty syntax-valid
filesystem-host outcomes agree (`all-library-corpus-oracle-results.json`). Previous
profiles remain separate baselines. Selected emitter libraries are not executed as
emitters by the current no-emit compiler operation.

`json-schema-emission.json` records native JSON Schema 1.16.0 emission of the official
Person/Address/Car sample using JSON output and explicit string int64 policy. All three
files match native filesystem-host output (`emission-oracle-results.json`). Seven
independent Python jsonschema cases cover bounds, required properties, unique arrays
and cross-file references (`emission-json-oracle-results.json`). Source YAML round trip
retains identical output. This is native emission evidence, not a lossless projection
claim; default compilation continues to disable emitters.

The authored `emission/numeric.tsp` fixture and both-policy before/after reports expose
native emitter 1.16.0 losses: unsafe literal rounding, missing int64/uint64 bounds and
missing numeric string syntax. Twenty-six independent Python comparisons show those
losses and verify the edited percent bound. All five emission cases (seven files) agree
with the native filesystem host. Passing these regressions means the losses remain
visible; it does not mean these emitted validators enforce the source domain.

`emission/projection.json` records the official sample's materialized native-emission
projection, including source, global risk report, target UMF and native target/resource
exports. Seven independent checks in `projection-oracle-results.json` validate the
re-exported target with its registered URIs. This proves target behavior survives UMF;
it does not establish complete source-to-target semantic fidelity.
