# Qualify the current primary integration under the original strict profile

The primary branch advanced and was renamed to `main` while the exact-source
40e qualification ran. Its new domain-pack loader, public-company and evolution
APIs must be preserved. The active action IDs now use US/TD/STP-900 because
primary independently allocated 078. CONTRACT-900/901 remain unchanged.
The exact per-file identity migration is recorded in
`evidence/actions-identity-migration-900.json`; original certificate identities
and hashes remain historical subjects.

## Acceptance profile

Complete and retain the strict 40e campaign, including all 174 native/browser
commands, six auxiliary commands, four complete disjoint regression shards,
17 admission tests, six integrity verifiers, final proof closure and 119 native
action tests. Its certificate describes that immutable source, not the later
merged source. Preserve the full certificate and logs under an immutable Git
commit and content-addressed retained inventory before replacing generated paths.

For this release, create a new exact-current-source strict certificate for one
frozen integrated source: rerun all 174 native/browser commands, six auxiliary
commands, all current disjoint regression tests, the original unchanged 17
admission tests, all six current integrity verifiers and 119 native action tests.
Also run current browser, metadata, native tutorial, formal and website checks.
Inherited native evidence is not counted as fresh. This retains the existing
source-fingerprint authority and avoids introducing a new evidence-admission
mechanism during delivery.

The reviewed alternative below is future design guidance, not the selected
release path and not an additional implementation requirement. If a future
release uses composition, create a separate composition certificate for one
frozen integrated source.
This certificate must label the 40e native campaign as inherited prerequisite
evidence and separately enumerate every freshly executed current command.
It must not rename inherited records as current, rewrite raw native fingerprints,
mock old-byte readers as current verification, or alter the existing strict
fingerprint guards. A support claim remains limited to the named versions,
subsets, native runtimes and evidence.

## Reviewed future alternative: executable composition admission

1. Validate the immutable baseline certificate, every prerequisite command/result,
   raw log, source inventory and proof-closure hash. Reject missing, failed or
   forged prerequisite evidence.
2. Pin the integrated commit and enumerate all additions, changes and deletions
   in complete source inventories. An exact reviewed delta admits every path;
   unlisted changes, missing paths and unused exceptions refuse admission.
3. Require identical pre-existing native, adapter, extension, validation and core
   implementations, schemas and toolchain inputs outside the exact reviewed
   exceptions. Require identical lock and native trees.
4. Admit the shared `preflightBytes` change only when replacing its single
   declaration with `export function preflightBytes` yields the exact new bytes.
   Admit only the exact reviewed additional index exports and loader subpath;
   removing those additions must recover the baseline bytes or package object.
   Pin the reviewed new initializer bytes; they cannot mutate existing validators.
5. Admit action-ID changes only through the enumerated old/new file transforms,
   with exact old/new SHA-256 and redirects. Public-company 078 is a different
   artifact and must retain its primary meaning.
6. Independently verify the actual execution source before and after fresh runs,
   full command inventories, pinned runtime image and dependencies, native
   container exits, closed raw logs and output hashes. Reject stale, incomplete
   or unlisted execution.

## Fresh execution and assertion allocation for the future alternative

Run current public-entrypoint and browser initialization, changed domain-pack
admission/export/loader/evolution tests, complete behavior regression, schema
validation and typechecks. Run action portable tests, all 119 native foundation
tests, all 44 shared browser cases, the actual native commit/rollback/refusal/
replay/query tutorial, metadata refusal controls and bounded formal analysis.
Validate all 21 action criteria against current executed canonical witnesses.

The eight strict admission files contain 17 tests and substantive behavior.
Every original assertion must have an explicit destination. Baseline execution
retains the original strict evidence, native enforcement and tampering controls.
Fresh integrated semantic checks retain field/nullability/cardinality round-trip
assertions, field group/kind and legacy recovery, facet coverage counts, key
identity/recovery controls, the relationship authored corpus and its nine
launched binding tests. Exact helper/test extraction must preserve the assertions;
composition admission precedes fresh behavior. No admission file may be dropped
wholesale as bookkeeping. Record that assertion allocation in machine-readable
form and verify it exhaustively.

The composition verifier must reject changed old implementation bodies,
omitted or extra delta paths, altered initializers or toolchains, forged or
missing baseline proof, incorrect identity mappings, failed prerequisites and
stale/incomplete current execution. Negative controls require a positive
baseline followed by the intended refusal, not a failure for an unrelated reason.
If a changed dependency's behavioral impact cannot be bounded, rerun its native
matrix; if the affected matrix cannot be bounded, rerun all 174 commands.

## Website and release

Preserve both primary-site packaging/research steps and action-guide checks.
Deploy only from `main`. Generate and check the ten beginner chapters and all
responsive diagrams, run public examples, verify all routes in real Chromium,
retain reviewed screenshots and exact HTML/asset hashes, and seal every final
configured page with the existing custody and pinned verifier.

Push the reviewed result, require CI success, merge to `main`, and verify the
actual merged Pages deployment. The live checks must compare served HTML/assets
to reviewed bytes and verify all page attestations. Cut and verify the scoped
experimental action release only after that deployment passes. Two beginner
reader sessions remain a usability follow-up; actual executable demonstrations
are mandatory.

## Review and unknowns

Astra Ultra reviewed the exact primary delta: existing adapter/action/validation
and native bodies are unchanged; `preflightBytes` gains only an export keyword;
new initialization creates private validators; domain-pack behavior changes.
Astra found composition defensible with the executable obligations above and
required complete assertion allocation for the original 17 admission tests.
The selected release path instead reruns the complete strict profile, so all
17 original admission tests execute unchanged on the current source. No extracted
assertions or new composition authority are used for this release.
This is design approval, not completed certification. Final command inventories,
certificate hashes, source revision, results and deployment URLs remain unknown
until their actual execution and audit. A later primary change requires a new
exact impact decision before merge.
