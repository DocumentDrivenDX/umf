# Core Record Type Rust candidate

This is an opt-in Rust core and tagged-JSON wire candidate for the current
`declareCoreRecordType` and `verifyCoreRecordTypeDeclaration` implementations
in `src/model/record-type.ts`. It preserves the public v6 receipt shape and
uses `core_kind` to recompute the nested Field and Record author receipts. The
core exposes separate receipt preparation and current-document finish phases;
the tagged operation carries both arguments and therefore does not qualify raw
host getter/admission order. The retained Rust binding runtime compiles its
static schema once at construction and holds the exact five resources and
compiled v6 receipt schema. `begin_finish` consumes and owner-checks the stage
before current admission; `seed_finish_context` carries receipt-phase work and
constraint counts into the context before current decoding. The host must use
that same seeded context for decode and finish. Opt-in Node/Bun and WASM host
interfaces have scoped source-slice replays; their evidence and freshness
limits are recorded in [`node-retained.md`](node-retained.md) and
[`wasm-retained.md`](wasm-retained.md). They have not been replayed as the
installed default SDK.

The implementation compiles the checked-in Core 0.10.0, kind-operation v6,
and Record-Type-operation v6 schemas from source. The wire request accepts only
the exact five Engine resources (`coreSchema`, `referenceSchema`,
`packageSchema`, `constraints`, `domainPolicy`) and no nonempty extension
registry. Unknown values inside the retained source/target remain part of the
receipt and are compared canonically. Only explicit Node/Bun and WASM factories
select the retained runtime; Python, CLI and default package routes do not.
Extension callbacks remain unavailable.

The frozen TypeScript predecessor packet is
[`frozen-typescript.json`](frozen-typescript.json), generated by
`scripts/rust-migration/r5/freeze-core-record-type.ts --check`. It pins the
record-type implementation, kind authoring dependency, copy/canonicalization
and validation dependencies, core/kind/record-type schemas, and three source
fixtures. It records three declaration and verification pairs and nine refusal
outcomes, including malformed receipt before current admission. The scoped Rust
wire test checks all three success pairs and exact outcomes for wrong author
order, malformed receipt, tampered receipt, stale current, scalar conflict,
facets conflict, existing record-type reference, and direct container type.
Those four conflict inputs are derived from the same pinned predecessor
fixtures. It does not exercise the `malformedReceiptBeforeCurrent` getter
control because tagged JSON has admitted both values before dispatch.

Target validation and the compiled v6 receipt schema run before a declaration
is returned. Schema and document validation diagnostics are emitted in the
Rust validator's order; exact diagnostic-string parity for broader `oneOf`,
semantic-extension callback, and malformed native/resource cases is not
established by this packet. Semantic extension callbacks are not available on
this wire profile. This is ideal authoring/receipt behavior only: it does not
establish native record-type interpretation, storage-system validity, or a
transactional write.
