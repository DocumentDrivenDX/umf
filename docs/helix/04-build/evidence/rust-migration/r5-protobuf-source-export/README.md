# R5 Protobuf source export prepare/finish

This packet records a bounded Rust preparation and finalization boundary for
`exportProtobufSources`. `prepare_source_export` validates the UMF Protobuf
document and encodes its current descriptor tree for an explicit host emitter.
The host supplies the emitter result and caller's current document to
`finish_source_export`; the source copy happens after result admission, matching
the TypeScript callback timing. A trusted callback that closes over and mutates
the caller's document can therefore make the returned source differ from the
descriptor bytes prepared before the callback; the frozen predecessor case
records that behavior explicitly. The core does not discover a compiler or
printer, start a process, read files, or use the network. The prepared value is
consumed once. The original source archive is carried in the returned source
document and is never used as emission input.

`finish_source_export` copies and validates the host result, requires a file
object plus JavaScript-truthy `compiler` and `printer` values (matching
predecessor admission), and requires emitted names to be nonempty and contents
to be strings. Unknown result fields are retained. The
returned `source` and `diagnostics` fields are core-owned; diagnostics preserve
the Protobuf inspection findings and append `PROTOBUF_SOURCE_LAYOUT`. Both
phases take the same operation `Context`; a final cooperative control check
occurs immediately before the final defensive copy. The host remains
responsible for invoking only a trusted installed emitter with the prepared
bytes and for honoring its own compiler/printer policy.
