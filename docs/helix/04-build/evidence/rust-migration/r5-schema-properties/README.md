# R5 core schema-properties Rust checkpoint

This checkpoint adds opt-in shared-core implementations of
`inspectCoreSchemaProperties` and `declareCoreSchemaProperties`. The Rust wire
operations preserve source, identity, patches, and unrelated unknown content;
Node/Bun and WASM model wrappers expose them without changing default routing.
Inspection carries the diagnostics produced by the single source validation in
identity location. Declarations use the core literal evaluator directly on the
selected, edited Field, matching the TypeScript predecessor's
`checkSchemaLiteral` ordering and diagnostic values.

## Frozen predecessor and scope

The exact TypeScript predecessor packet is
[`frozen-typescript.json`](frozen-typescript.json), generated by
`scripts/rust-migration/r5/schema-properties/freeze-predecessor.mjs`. It freezes
document/module/element inspection, declaration, patch-before-source and
source-before-identity refusal order, unknown relevant facet refusal,
unrelated unknown facet preservation, caller-copy isolation, and JSON/YAML
round-trips. The retained TypeScript suites passed 58 tests / 439 assertions
before implementation and again after it. The TypeScript predecessor source
remained unchanged. The packet was finalized with an explicit `inputs` block
before Rust differential validation; an earlier capture without that block
had SHA-256
`853292803b6c262e40f0e4136707fbd71cbf872ca2783c876519717eb12894e5`. The
final packet below includes those request inputs and was not refreshed to match
Rust.

An additional literal diagnostic probe verifies that invalid `allowedValues`
and `default.value` declarations both refuse with the predecessor's exact
`CORE_SCHEMA_PROPERTIES` code, `Expected exact JSON numeric token` message, and
empty path. This matters because validating the whole document before checking
the literal would change the first refusal.

scope returned `Explicit identity required` before checking unknown identity
members. The TypeScript predecessor derives an empty allowlist for those scope
