# R8 PostgreSQL schema authority checkpoint

## Scope and finding

This checkpoint classifies four PostgreSQL schema resources whose authority was
unresolved in the R8 census. CONTRACT-015 directly identifies the versioned
representation schema for `umf.postgresql` 0.1.0 and the separate
`umf.postgresql.catalog` 0.1.0 tagged representation and capture schema. The
ledger therefore records these three files as authored normative contract
schemas:

| Resource | Versioned `$id` | Authority |
| --- | --- | --- |
| `spec/extensions/postgresql/schema.json` | `urn:umf:postgresql:0.1.0` | CONTRACT-015, US-015 AC1/AC3 |
| `spec/extensions/postgresql-catalog/schema.json` | `urn:umf:postgresql-catalog:0.1.0` | CONTRACT-015, US-015 AC6 |
| `spec/extensions/postgresql-catalog/capture.schema.json` | `urn:umf:postgresql-catalog:capture:0.1.0` | CONTRACT-015, US-015 AC6 |

The ledger records `spec/extensions/postgresql/native-ast.schema.json`
(`urn:umf:postgresql:native-ast:0.1.0`) as generated by the exact writer
`scripts/postgresql-schema.ts`. The writer reads the pinned
`native/postgresql/protobuf/pg_query.proto` descriptor and manifest, parses it
with `@launchql/protobufjs` 7.2.6, and checks the reflected codec from
`@libpg-query/parser` 17.6.10. It checks descriptor identity, field inventory,
enum values and per-field wire encodings before emitting the schema and
`native/postgresql/protobuf/schema-evidence.json`. CONTRACT-015 and US-015
AC1/AC3/AC4 govern the native AST preservation profile. The generator's
`--check` mode passed for this source cohort.

The catalog package manifest embeds a copy of its representation schema, and
the adapter imports the standalone schemas. This correspondence does not
establish a generator for the package copy; the ledger does not label it as a
generated output. The check-in checkpoint commit is not used as authorship
proof. Schema contents and IDs are hash-pinned with the applicable contract,
story, consumers and SDK copy/archive rules.

## Limits

The native AST schema represents descriptor fields and oneof structure, not
SQL grammar, catalog validity or database execution. The generator records 272
messages, 71 enums, 1,665 fields and 4,560 field wire vectors for the pinned
cohort; its own evidence states that nested empty-message probes are not
semantic proof and the wire probes are not an exhaustive AST corpus. The
catalog contract is the declared PostgreSQL 17 observation profile, not all
of `pg_catalog` or server state.

The ledger closes source/build/archive rules for these resources. It does not
qualify a production SDK archive or installed resource bytes, and it makes no
default-route retirement claim. The authority entries are explicit and
history-independent; normal ledger regeneration does not require the original
Git history objects. No shared inventory or ledger snapshot was regenerated in
this tranche.

Focused verification:

```sh
node --test --test-name-pattern='PostgreSQL contract schemas have bounded authority' scripts/rust-migration/r8/gap-ledger.test.mjs
bun scripts/postgresql-schema.ts --check
```

The ledger test checks the four exact schema IDs, the per-resource governing
clauses and source closures, generated writer inputs, and the
`not-installed-qualified` archive status. The generator check verifies the
current output against its pinned descriptor/codec inputs; neither test proves
installed archive bytes.
