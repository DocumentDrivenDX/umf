# Expanded CSV Boolean acceptance packets

These generated packets cover the two default-route operations
`validateCsvBooleanLexical` and `verifyCsvBooleanLexical` under draft
CONTRACT-053's explicit `umf.csv-boolean-lexical/1.0.0` profile. The packet
outcomes are regenerated from the TypeScript predecessor. Their acceptance
surface now includes the four lexical tokens, public Boolean constraint and
unknown-semantics verdicts, String Field refusal, map cardinality, old core
version, unsupported token classes, missing/null/wrong-type request values,
forged receipt components, and prepared-source versus zero-call verifier
preflight behavior.

Paired input-size cases reconstruct an otherwise valid request carrying the
intentionally unsupported but JSON-valid token `TRUE`. The UTF-8 JSON encoding
of `{source, request}` is exactly 4,000,000 bytes in one case and 4,000,001 in
the other. The exact case reaches request validation and returns
`CSV_BOOLEAN_LEXICAL`; the over case returns `LIMIT` at the input budget. Each
runner recomputes and asserts both byte counts. This repairs the historical R5
fixture, whose exact-size request omitted the required token and therefore
stopped at request-shape validation. Paired receipt cases also cover exact and
over-by-one 4,000,000-byte output and verification-receipt budgets.

Each CSV case is replayed through the installed default and explicit reference
routes. Host receipts record exact outcomes, callback traces, per-case Rust
call counts, packet hash, runtime, archive hash, source-closure hash, and
entry/artifact hashes. Reference-route Rust calls must remain zero. Cases marked
`expectsRust` require at least one default-route Rust call; preflight cases
require zero. The harnesses support Node, Bun, and real Chromium on the declared
macOS arm64 and Linux x64 cohorts.

The separate `validateCoreRecordValues.packet.json` uses the distinct
`umf.r8.csv-boolean-record-presence-packet/1` format and preserves present-null and
absent as distinct Record states for `patients.active`; it asserts that no
default is inserted. The current V4 facade still routes this operation through
TypeScript. Its default/reference receipts therefore record zero Rust calls,
and the packet is explicitly outside the two-operation Rust retirement
manifest. It is a scoped control, not Record API retirement evidence.

The 18 adversarial host-object controls are frozen as 17 validation cases and
one receipt-first verification case. They cover accessors and hidden data,
symbol keys, competing invalid members, invalid-request precedence, proxy
reflection exceptions, changing descriptors/key lists, reflection order, and
malformed-receipt precedence. The original historical comparison remains in
the [CSV default-route review](../r8-csv-boolean-default-route/retirement-review.md).

The expanded packets were replayed on Node 26.12.1, Bun 1.4.3 and real
Chromium 153.0.8010.12 against the fixed-point d5 archive
`7105a7f69118367cefe1e156481a6e3c85bad49c63157f1956f85dcef52383e2` with
source closure
`d5e1783d7f615c8c1877df4f3d9ded43e68039f6b8f4d307e13ea79c190fa8f9`.
All 44 validation, 17 verification and two Record cases matched the frozen
TypeScript outcomes and traces on each host. The 4,000,000-byte pair was
reconstructed and checked in each runtime. Chromium confirmed Node globals were
absent. Default Rust-call vectors matched across the three hosts: validation
cases 18–43 recorded Rust calls, while the 17 host controls and final
source-accessor preflight recorded zero; verification call counts were
`[2,2,2,2,2,2,2,2,2,2,2,1,2,1,1,0,1]`. All reference routes recorded zero Rust
calls. Record controls also recorded zero.

Raw receipts are retained under [`d5-diagnostic/`](d5-diagnostic/). This is
diagnostic use of an older archive: its source closure predates these packets
and runners, so the receipts do not qualify the expanded packet source closure
or establish current-source retirement evidence. Rebuild and replay both
fixed-point cohorts after the packet and harness source has been captured.
No ledger row is retired, and no general CSV conversion, full SDK parity,
TypeScript declaration retirement, merge, or release claim follows.
