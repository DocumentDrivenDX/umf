# Unified action admission continuation

The unified generator reaches standalone `admitAction` followed by profile/native
dependency gates and only then `analyzeAction`. These helpers preserve those phases
and use the supplied standalone action schema, prepared policy, empty-registry
core validation and the invocation Context. The module payload schema does not
gate this narrower entry point.

`analysis.json` freezes eleven direct predecessor admissions. `bounds/analysis.json`
adds combined-condition and raw UTF-16 expression limits. Their public compiler
equivalents are the six and two cases in the corresponding `frozen.json` files.
No predecessor expectation was refreshed. The propertyNames and ref-free false
definition assertions additionally check supplied-schema diagnostic presentation.

Admission first copies the raw JSON at the original limits, then applies JavaScript
own-key order locally. Only trusted schema evaluation receives a temporary same-
Context depth allowance. The new opt-in core error presentation retains failed
combinator branches; the action formatter preserves Ajv schema paths, custom
equality diagnostics and optional propertyName metadata. The ordinary core
validation presentation retains its existing mode.

`repair-checkpoint.json` records the source hashes and changing-source native
feedback. All owned action/binding controls pass. Two additional binding-identity
controls expose separate access-generation errors and remain pending with that
owner. Independent review and the installed-host cohort remain required.
