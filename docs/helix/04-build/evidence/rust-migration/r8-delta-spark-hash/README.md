# R8 Delta Spark hash operation

## Scope

This receipt covers one public logical operation: `sparkStringHash`, a scalar
used by Delta multipart checkpoint clustering. It does not port multipart
reconciliation, checkpoint recovery, or the Delta family. It does not change
default routes. The Rust core function is `umf_core::delta_spark_hash::spark_string_hash`;
the opt-in wire entry point is
`umf_core_wire::delta_spark_hash::execute_json` with operation name
`delta/sparkStringHash`.

## Source and predecessor binding

The predecessor is `src/adapters/delta/spark-hash.ts`, SHA-256
`e2fff4f2f4c9a6684d4bda80bc9fa0681ccd339bc20ef665349768b4536865b0`.
It specifies Spark 4.0.1 legacy Murmur3 over UTF-8 bytes, seed 42 by default,
null passthrough, and signed individual tail bytes. The frozen 26-case outcome
set is `fixtures/delta/multipart/hash-vectors.json`, SHA-256
`2cabad4989a251c796d9aa545668b6afb7d0bdc9c892dae71ccd9bf245f7818e`.
It is generated by `scripts/delta-multipart-probe.py`, SHA-256
`687bbf8dd2bf62eafa14f8e8125222c6622d072c1a0b390a5c39e2a68c8f5996`, which
calls Spark's JVM `Murmur3HashFunction` and records the Spark 4.0.1 runtime
label in the fixture. The contract records the independent runtime boundary
as Spark 4.0.1 and OpenJDK 21.0.2 (CONTRACT-018, multipart section).

The Rust unit vectors cover null and 12 string inputs (empty, ASCII tails,
accented/CJK/emoji UTF-8, and checkpoint-like paths), each at seeds 42 and
-12345. The core unit suite and the wire test use these predecessor outcomes;
the wire test additionally exercises request decoding, operation dispatch,
response encoding, and rejection cases.

## Verification

Run the core test and wire test with:

```sh
PATH="$(dirname "$(rustup which cargo)"):$PATH" CARGO_TARGET_DIR=/tmp/umf-delta-hash-target cargo test -p umf-core delta_spark_hash --lib
PATH="$(dirname "$(rustup which cargo)"):$PATH" CARGO_TARGET_DIR=/tmp/umf-delta-hash-target cargo test -p umf-core-wire --test delta_spark_hash_wire
```

The request format is bounded JSON with `op`, `value` (string or null), and an
optional signed 32-bit `seed`. The result is JSON with one signed 32-bit
`hash`. This wire entry point is opt-in; the general host dispatcher and SDK
bindings do not expose it. Rust strings cannot contain unpaired UTF-16
surrogates, so that JavaScript-only input rejection case is outside this Rust
operation's domain.

## Delta exact-tree candidate map

The next bounded candidate is the eight schema/table source operations:

| Profile | Import | Export | Copy access | Atomic candidate edit |
| --- | --- | --- | --- | --- |
| `umf.delta` | `importDeltaSchema` | `exportDeltaSchema` | `getDeltaNode` | `proposeDeltaNodeEdit` |
| `umf.delta.table` | `importDeltaTable` | `exportDeltaTable` | `getDeltaTableNode` | `proposeDeltaTableNodeEdit` |

The authoritative sources are `src/adapters/delta/index.ts` and
`src/adapters/delta/table.ts`; their schemas are under `spec/extensions/delta/`
and `spec/extensions/delta-table/`. The behavior is exact-tree preservation,
not native normalization: unknown source properties/types survive, exact number
tokens survive, access returns copies, edits operate on a copied candidate,
known-shape failures reject candidates, and unknown representation/tagged-tree
fields block export. CONTRACT-018 requires the schema and supplied table
context to remain distinct and does not infer protocol validity, table snapshot
validity, or safe evolution.

The TypeScript tests are `tests/delta/schema.test.ts` and
`tests/delta/table.test.ts`; the schema corpus is 39 inputs with 37 exact
round trips and two structural rejections, and the table tests pin embedded
schema spelling, int64 creation time, unknown future features, malformed
embedded schema retention, immutable edits, and representation guards. Existing
native and browser evidence is linked by CONTRACT-018 and stored under
`fixtures/delta/`. The Rust core now has separate schema and table-context
candidates in `crates/umf-core/src/delta_schema.rs` and `delta_table.rs`. They
remain core-only operations: no wire, host binding, or default route is
admitted. Schema corpus coverage records 37 byte-exact round trips and two
expected structural rejects. Focused tests cover schema warning order,
table round-trip/access/edit immutability, and pointer-before-replacement
ordering. The five-family TypeScript warning receipt is
[`delta-warning-predecessor.json`](delta-warning-predecessor.json); Rust tests
compare ordered code, path, and message for unknown properties/types, Unicode
duplicate names, decimal grammar/range, feature/void, metadata, and map default
nullability. Structural error strings are tracked separately and are not
claimed as exact parity. Table semantic warning parity remains incomplete.
[`delta-table-numeric-predecessor.json`](delta-table-numeric-predecessor.json)
records eight TypeScript numeric boundary outcomes for protocol versions and
`createdTime`; focused Rust tests reproduce the binary64 rounding, integer,
minimum, overflow, and diagnostic-order results.

The schema validator's temporary shape view maps every exact native number
token to `0.0`; resource creation rejects numeric `type`, minimum/maximum,
exclusive bounds, `multipleOf`, and numeric `const`/`enum` assertions before
that view is used. A future numeric grammar change fails closed with
`DELTA_GRAMMAR_NUMERIC_RULE`. The table grammar guard admits exactly the
`minReaderVersion` and `minWriterVersion` integer types with minimum 1, plus
the nullable-integer `createdTime` type; any moved, removed, or added numeric
assertion fails resource construction. Table numbers are checked at the same
binary64 boundary as TypeScript's JSON view before the projection maps tokens
to `1.0`; boundary receipts and tests cover rounding, exponents, fractions,
minimum errors, and overflow. The original `NativeJsonTree` remains the
export/edit authority in both profiles.

The first source capture is recorded in

`9870d013031c7c7024ef0277ffcf8329775b61e1713e817dc30bc88a19762c70`.

The core-only schema/table source candidates now have an opt-in tagged JSON
wire entrypoint, `umf-r8-delta-source/0.1.0`, for exactly ten operations:

The current TypeScript table-context diagnostics are frozen in

The receipt includes source and runner hashes, exact native inputs, and ordered

feature/version rules, embedded schema warnings, partition resolution,

covers empty history, a version gap, missing initial metadata, duplicate
protocol actions, and a single version-zero state with a large exact `txn`
version, `commitInfo`, and an unknown action retained as deferred content. New
cases verify cross-commit `Map.set` replacement order for transactions, domain
metadata, and adds; a same-commit add/remove conflict; and a later remove
clearing a prior add; and a `txn.appId` containing an isolated UTF-16 surrogate.
The freeze packet represents that TypeScript identity as UTF-16 code units so
the JSON packet remains portable. Four added histories freeze ordinary
deletion-vector transitions: same-path/same-vector replacement keeps map
position, changing a live vector without removal is refused, removing the old
vector before adding the new one retains the tombstone, and repeated/unknown
removals retain tombstone order. Rust explicitly returns `DELTA_HISTORY_UTF16`
before identity conversion and retains the full source; the other twelve cases
compare full results, ordered diagnostics, and state.

## Limits

The hash operation does not establish the validity of multipart filenames,
checkpoint metadata, table protocol features, or a recovered Delta snapshot.
`complete:false` remains the family-level posture. These candidates do not
establish native Delta reader/writer support, transaction-log reconciliation,
commit, or safe evolution. No default route or SDK admission is claimed.
