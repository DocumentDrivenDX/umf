# R5 core Key default-route qualification

This packet freezes the public TypeScript Key and Record membership operations,
including raw host admission order, error names, result object prototypes, and
a 700,000-unit retained-value control. The bounded Node/Bun/browser default
route selects `inspectCoreKeys`, `lookupCoreKey`, `declareCoreRecordMembers`,
and `declareCoreKey`. `verifyCoreKeyOperation` remains on TypeScript because
Rust's staged receipt preflight followed by finish recomputes and meters receipt
admission twice, and null-receipt host error order has not been qualified.

The predecessor packet is generated by
`scripts/rust-migration/r5/freeze-core-keys-default.ts`. It pins each local
source input by SHA-256. Qualification remains open until the installed
artifact passes the same captured outcomes in Node, Bun, and real Chromium,
including malformed request-before-source behavior and resource controls.
The Rust opt-in verifier remains independently tested; it is not selected as a
default route in this packet.

## Verification selection decision (2026-10-24)

`verifyCoreKeyOperation` remains TypeScript. The immutable predecessor packet
[`frozen-typescript.json`](frozen-typescript.json), SHA-256
`3ee774e9d623c18f1d109cb9f6ce86b4c0957be24bd874c74fc6c375aa593323`, pins
`malformedReceiptBeforeCurrent`, null and primitive receipts, a valid receipt
with an accessor on `current`, result prototypes, and verification of a
700,000-unit retained unknown qualifier. Its expected malformed-receipt result
is `CORE_KEY_RECEIPT` before host admission of `current` begins; the current
getter must remain uncalled.

A one-call tagged wire request cannot preserve that ordering: the host must
encode both `receipt` and `current` before Rust dispatch. A Bun probe using
`encodeRequestWire` with the frozen malformed receipt and an accessor on
`current.future` demonstrated host inspection and refusal
(`AdmissionError`, `ACCESSOR_PROPERTY`, path `/current`, zero getter calls)
before Rust could return the predecessor's receipt error. The current staged
binder in [`rust-keys-default.ts`](../../../../../../src/access/rust-keys-default.ts)
preserves receipt-before-current ordering, but the key-operation wrapper's
`finishCoreKeyVerification` dispatches `model/verifyCoreKeyOperation` again,
repeating receipt recomputation and metering. Rust's preparation and full
verification paths are in
[`core_keys.rs`](../../../../../../crates/umf-core/src/core_keys.rs); generic
operation dispatch is in
[`core wire`](../../../../../../crates/umf-core-wire/src/lib.rs), and the
host encoder behavior is in
[`wire.js`](../../../../../../bindings/core/wasm/src/wire.js).

A finish operation that accepts ordinary prepared JSON and only compares its
target to `current` would also be forgeable through the generic wire dispatcher.
The negative control mutates the frozen valid receipt's retained
`request.name` while keeping `current` equal to its target: target equality
alone passes, while the TypeScript verifier correctly refuses with
`CORE_KEY_RECEIPT` / “Operation differs from retained source/request”. The
existing Rust cardinality finish path likewise revalidates prepared JSON
because its tagged operation is directly dispatchable; see
[`cardinality.rs`](../../../../../../crates/umf-core/src/cardinality.rs).
Avoiding both hazards requires
an unforgeable Rust-owned prepared verification handle shared by Node and WASM;
that interface is outside this bounded default-selection slice.

The probes leave the frozen packet untouched. Its captured TypeScript source
closure currently differs at `src/generated/core-model.ts`,
`src/generated/core-validators.ts`, `spec/core/schema.json`,
`spec/metamodel/generated/core-constraints.json`, and
`spec/metamodel/generated/domain-policy.json`, so the packet remains a
historical predecessor capture rather than a current-source closure receipt.
Existing Sol review in
[`r5-core-keys`](../r5-core-keys/README.md) covers the Rust core operations;
Sol has not reviewed default-route selection or the two probes recorded here.
No selector, binder, or root-entry change is made, and no installed Node/Bun or
Chromium qualification is claimed for this default route.
