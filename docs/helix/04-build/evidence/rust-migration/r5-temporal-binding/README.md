# R5 temporal binding slice evidence

This evidence qualifies only the additive, resource-free `createTemporalEngine()` API for `umf-gregorian-date/1.0.0` and `umf-rfc3339-exact-instant/1.0.0`. Existing `createEngine()` defaults remain unchanged; the retained TypeScript adapters remain the reference implementation. No bare core date or timestamp semantics are selected implicitly.

The independent fixture is generated by `scripts/rust-migration/r5/temporal-binding-fixture.py`, using Python `datetime.date`, `datetime.datetime`, `datetime.timezone`, and `timedelta` for five calendar boundaries and five instant boundaries. Its canonical compact JSON SHA-256 was `0a98b71747c58353d460daf13d6e8c3fff01339dfac5ef11fc3a5e1b1b5f4741`. It includes years 0001 and 9999, leap day, negative epoch seconds, arbitrary fractional precision, case-preserving RFC3339 tokens, numeric offsets, and the unknown local offset marker `-00:00`.

`temporal-binding-node.ts` compares the staged release N-API package against both the independent fixture and retained TypeScript helpers. It checks frozen engine/result objects, source retention, truncation, instant equality, offset unknownness, and built-in `TypeError`/`RangeError` identity. The actual staged package passed on Node `v26.12.1` with all 10 fixture rows. An initial run exposed N-API's trailing UTF-16 sentinel; the bridge now drops only that terminal code unit and preserves embedded NULs.

`temporal-binding-browser.ts` exercises the generated `wasm-bindgen 0.2.100` web package in Chromium `153.0.8010.12`. It passed all 10 fixture rows, frozen-result and error-class checks, and confirmed `process` and `Buffer` are absent from the browser global scope. Build inputs were `umf-core-wasm` release for `wasm32-unknown-unknown`, `wasm-bindgen 0.2.100`, and the checked-in WASM wrapper.

Validation also included `cargo check -p umf-core-node -p umf-core-wasm` and `bun run typecheck`. To repeat runtime checks, build the Node addon and wasm32 library, generate the `--target web` package with `wasm-bindgen`, stage `bindings/core/node/index.js`, `bindings/core/node/src/wire.js`, and the release addon in a private package directory, then set `UMF_R5_NODE_PACKAGE` to that staged `index.js` and run `temporal-binding-node.ts`. Place generated WASM wrapper files under the local `pkg/` directory beside `bindings/core/wasm/index.js`, serve the package on localhost, and run `temporal-binding-browser.ts`.

This is adapter-kernel and binding evidence only. The public default API cutover, Python binding integration, downstream family adapters, broader UMF semantics, and TypeScript retirement remain open.
