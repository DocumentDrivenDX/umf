# R7 codegen host-read Gate 0

This evidence freezes the direct root API `generatePythonClient` request
boundary before any Rust default cutover. It characterizes the current
TypeScript implementation, not CONTRACT-067's separate stage-one
`generateAccessPackage` surface. The opt-in V2 snapshot API and the default
entrypoint were not changed.

## Host parity and fixtures

`bun test tests/access-host-read-gate0.test.ts` runs one dependency-free probe
against the direct function in Bun, a fresh browser-target bundle imported by
Node, and that same bundle in real Chromium. All hosts returned byte-identical
probe observations. Captured versions were Bun `1.4.3`, Node `v26.12.1`, and
Chromium `153.0.8010.12`; Chromium made zero external requests. The test passed
46 assertions.

The source fixture is `tests/unified/commerce.json`; its SHA-256 is
`19c018888066d391599d4bc8079ec8f3479266e6ecc55237c57825bc33c3003d`. The
native-table fixture is generated by
`tests/unified/table-operation-fixture.ts` (SHA-256
`81cfab25e02f16d99fd653b76b5fdd359b175071b9be74936e92c1fa4991aab4`). The
complete Bun browser-bundle input closure contains 218 files and is pinned in
[`source-closure.json`](source-closure.json), with digest
`e5be416acfaaf116999163188f311deec8c34604791389e31291e2fdaac0c136`. It
includes vendored schema/resources and the locked Ajv `8.20.0` and YAML
`2.9.1` runtime sources. The manifest also pins the commerce fixture, table
fixture helper and generated table fixture, the shared probe, this test, the
package manifest/lockfile, Playwright package metadata, and exact runtime
versions; the test checks those pins before host execution.

## Frozen behavior

For a valid request represented by a Proxy, the exact stable `get` sequence is:

```text
text, package, package, package, package, text, format, text, records, actions,
package, package, package, package, text, package, package, package
```

The four `text` reads serve different steps: initial type check, document parse,
source digest, and emitted `shop/source.json`. With a changing getter, the
digest is independently pinned to SHA-256
`3fe6890d8e7a55f5f9155ff71b484a2118df8c218b30a15f243ecbf5d52ff807` from its
third value while the fourth value is copied into `source.json`. The API returns file entries; it does not read an archive or
filesystem path. An extra throwing `archive` getter remains untouched. The
stable output paths are `shop/__init__.py`, `shop/models.py`,
`shop/_runtime.py`, `shop/source.json`, `shop/description.json`, `shop/py.typed`,
and `shop/_umf/manifest.json`.

Package handling is observable too. Initial validation reads `package` four
times (truthiness, regular-expression coercion, keyword lookup, reserved-name
lookup); later construction reads it once for each generated path. A changing
package getter therefore yields seven independently varying output directories.
An invalid package after valid `text` reads `text` once and `package` twice,
then throws `UmfError(ACCESS_UNSUPPORTED, path=/package)` without reading
`format`, `records`, or `actions`. If the first `text` getter throws, its exact
exception occurs before the invalid package is read. A valid request calls the
`format` getter during parsing; an exception from that getter propagates
unchanged.

`records` and `actions` each get read twice when truthy: once for the condition
and once to obtain `.map`. The custom map result is consumed by `new Set`, so a
map returning a Set remains accepted. Exceptions from the second getter, a
custom iterator, or the `actions.map` getter propagate unchanged. Record module string coercion occurs
before reading the record's `element`; a throwing `Symbol.toPrimitive` escapes
as the original error. The selected-record and selected-action cases preserve
their exact generated results. Invalid source text fails before a `records`
getter runs. A truthy first `records` or `actions` read followed by a throwing
second getter propagates the second exception unchanged. For a native-table
request, `format` is read first by the parser
and a second time by the native-format restriction. A getter returning `json`
then `yaml` produces `ACCESS_UNSUPPORTED` at `/format`.

These are compatibility observations, including deliberately dynamic getters;
they are not recommended request patterns. The direct API has not been
normalized to remove them.

## Rust boundary proposal

The current V2 facade snapshots `text`, `package`, `format`, `records`, and
`actions` once in a fixed order. That is a useful versioned API contract but it
cannot preserve the observations above. In particular, V2 changes accessor
counts, the first refusal for crossed invalid-package/accessor inputs, and the
relationship between digest text and emitted `source.json` for a dynamic text
getter. Keep V2 opt-in and keep the root default on TypeScript until a reviewed
compatibility decision is made.

If default Rust execution must retain this legacy behavior, a one-shot request
snapshot is insufficient. The engine needs a synchronous host-read protocol
that requests reads at the same semantic checkpoints and propagates raw host
exceptions unchanged. A proposed event sequence is:

1. `InitialTextType`, then the ordered `PackageTruthy`, `PackageRegex`,
   `PackageKeyword`, and `PackageReserved` expressions.
2. `ParseText` and the first `ParseFormat`, followed by Rust's parse and current
   source-version gate.
3. `DigestText`, followed by record selection's `RecordsTruthy` and
   `RecordsMap` calls; the host performs JavaScript `.map`, `refId` coercion,
   and `Set` construction and returns ordered selected IDs.
4. Rust determines `NativeSelected` from the parsed document and selected
   records. Only when true, it requests `NativeFormat`, the second format
   getter read, and refuses unless that value is `json`. This checkpoint is
   before native-table client preparation and before later action selection.
5. After record/relationship validation, `ActionsTruthy` and `ActionsMap`; the
   host performs the original JavaScript calls and returns selected IDs.
6. Output callbacks follow source construction order: `OutputPackage` for
   `__init__.py`, `models.py`, `_runtime.py`, then conditionally
   `_table_runtime.py` when a native module was selected, and then `source.json`;
   immediately after that path read, `OutputSourceText`
   supplies the fourth text value.
   Remaining `OutputPackage` reads produce `description.json`, `py.typed`, and
   `_umf/manifest.json`.

Dynamic package accessors can return a different valid package for each output
path; the test pins seven directories for the ordinary request and eight for
the native-table request.

The native Node binding and WASM binding would need the same synchronous callback
contract. The callback must read properties with the original request as the
receiver, preserve proxy/getter order and identity, perform JavaScript coercion,
`.map`/iterator behavior, and rethrow the original exception object. The test
checks `caught === sentinel` before serializing every targeted raw-exception
case in each host. Rust must not combine the digest-source and output-source
reads or precompute package paths. Gate 0 does not prove that such a cross-language callback is practical or
safe; this is an interface proposal for review. If the callback cannot preserve
these host semantics, the choices are a reviewed versioned API boundary or
retaining the legacy TypeScript entrypoint.

## Reproduction and source identity

Run `bun test tests/access-host-read-gate0.test.ts`. The test builds the exact
current `src/access/index.ts` closure for the Node and browser comparison and
checks its 218 input hashes against `source-closure.json` before executing the
host matrix. The probe and test SHA-256 values are pinned in `source-closure.json` under
`harnessInputs`; see those rows after running the reproduction command for the
current values.

This Gate 0 does not qualify semantic parity for the Rust candidate, other
codegen operations, a package release, or a default cutover.
