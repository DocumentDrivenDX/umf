# R7 standalone browser WASM package

The extracted `@umf/core-rust-wasm` 0.1.0 tarball is self-contained for the
captured browser binding cohort. Its entrypoint imports the wire, JavaScript
numeric and `umf-128/1` helpers from package-local files. The checked-in package
copies are generated byte-for-byte from the authoritative Node binding sources
by `scripts/rust-migration/r7/wasm-package-sources.ts`; the generated manifest
records each source path and SHA-256. `--check` rejects stale copies. The
package `prepack` hook refreshes those files, and the package file allowlist
includes them alongside the built wasm-bindgen JS and WASM files.

`scripts/rust-migration/r7/wasm-package-qualification.ts` packs with Bun 1.4.3,
extracts the resulting npm-compatible `.tgz`, verifies required files and every
relative JavaScript import against the extracted tree, then runs Node, Bun and
Chromium against that extracted directory. It does not copy repository wrapper
or helper sources into the browser host. Chromium served only the extracted
package plus frozen input data.

## Qualification

- `bun pm pack` produced `umf-core-rust-wasm-0.1.0.tgz`, SHA-256
  `4ba7ea549492c27c25ad57564e2e6a353fd754299e4fc0c223a484a16b0b08bb`.
- The tarball contains the package entrypoint and declarations, local
  `core-model.js`, generated wire/numeric/bit128 helpers, the helper hash
  manifest, and the actual built `pkg/umf_core_wasm.js` and
  `pkg/umf_core_wasm_bg.wasm`. No package dependency or import reaches outside
  the extracted directory.
- Node 26.12.1 and Bun 1.4.3 imported the extracted entrypoint, initialized the
  packaged WASM from its bytes, and passed core copy plus bit128 operation
  smokes.
- Chromium 153.0.8010.12 imported the extracted package over loopback. Core
  copy/JSON operations passed; all 389 independent bit128 oracle vectors
  passed; the accessor control read no getter; bit128 work metering reported
  1,507 units and cancellation returned `CANCELLED`.
- All 50 frozen Field-value predecessor cases passed, including 11 native
  browser `TypeError` outcomes. Metering reported 27,593,133 units and
  cancellation returned `CANCELLED`. `process` and `Buffer` were absent in the
  browser.

The browser execution establishes self-containment for these opt-in core,
bit128 and Field-value surfaces under this source and artifact cohort. Earlier
R5 staged-binding receipts remain historical and are not relabeled as
extracted-package tests. This evidence does not establish R7 default cutover,
TypeScript retirement, the full browser export surface, release publication or
any broader native adapter support.

## Reproduction

Using Rust 1.90.0, wasm-bindgen CLI 0.2.100, Bun 1.4.3, Node 26.12.1 and
Playwright Chromium 153.0.8010.12:

```sh
PATH=/Users/erik/.rustup/toolchains/1.90.0-aarch64-apple-darwin/bin:$PATH \
  CARGO_TARGET_DIR=/private/tmp/umf-r7-wasm-target \
  cargo build --locked --release --target wasm32-unknown-unknown -p umf-core-wasm
/private/tmp/umf-r7-wasm-bindgen-cli/bin/wasm-bindgen --target web \
  --out-dir /private/tmp/umf-r7-wasm-pkg \
  /private/tmp/umf-r7-wasm-target/wasm32-unknown-unknown/release/umf_core_wasm.wasm
bun scripts/rust-migration/r7/wasm-package-sources.ts --check
UMF_R7_WASM_BINDGEN_PKG=/private/tmp/umf-r7-wasm-pkg \
  bun scripts/rust-migration/r7/wasm-package-qualification.ts
```

The qualification script builds and removes the ignored package-local `pkg/`
staging directory, leaving the package tarball and extracted fixture under the
system temporary directory for inspection. It also runs the separate
`wasm-package-runtime.mjs` and `wasm-package-browser.ts` harnesses against that
extraction.
