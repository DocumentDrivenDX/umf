# G11 journal family ownership and pure ROOT replay 001

Clarification of adopted governing014/015, not a new native provider or an
enlargement of the known definition tuple. The tuple has non-null rootEvents
and originalsEvents, but null ingressEvents and applicationEvents.

ROOT owns exactly generation-authority-observed, generation-authority-root-
mutation-intent, generation-authority-root-mutation-confirmed and generation-
authority-bound. Its full signed pure replay positive remains required. A null
ingressEvents does not disable these ROOT grammar branches or replace positive
ROOT transition/confirmation/binding tests with refusals.

ORIGINALS owns only the separately adopted G04 typed original-store creation
grammar and its exact generic native-effect parent association. It must not
admit an ingress-store profile as an alias of a G04 reservation. Null ingress
means the separate ingress creation/reservation/attempt/COMMIT lifecycle grammar
is unavailable until explicitly adopted in a fresh complete known definition
and original enrollment/header. Existing definitions are never widened in place.

Pure ROOT replay validates canonical observation data, original event-reference
associations, full signed ROOT transitions and exact checkpoint sequencing. It
does not create a registered native observation or prove original ingress birth.
In particular it must not manufacture that prerequisite by accepting an
ingress-profile ORIGINALS reservation. A full pure signed ROOT test uses clearly
synthetic canonical observation data directly, without a fabricated ingress
creation history, and remains labelled source/data evidence. Actual cryptographic
transition verification is still exercised; fixture data confers no capability.

At the actual native issuer/writer boundary, governing014's genuine committed
ingress receipt, original custody, complete closed native snapshot, same-target
continuity and current facts remain mandatory. That boundary is unavailable
until its actual owning creator/provider and separate fixed ingress grammar are
implemented/adopted/verified. A successful pure ROOT codec does not authorize
production ROOT reserve/confirm/bind or issue an owner context. The current
null-ingress tuple cannot perform a new ingress creation just because ROOT
syntax is understood. Full positive native ROOT acceptance remains required
for the backlog; this separation is not permanent refusal as completion.

NativeEvidenceDigest in a mutation retains the ORIGINAL signed snapshot digest.
ValidationObservationEventDigest may reference a later fresh native observation
with a different evidence digest. Do not impose byte/hash equality between them.
The actual native provider proves same-target continuity and legitimate changing
facts. The codec must at least reject noncanonical/non-JSON/non-object observation
bytes (including duplicates, invalid UTF-8, floats and trailing whitespace), keep
the complete bounded canonical object bytes and their digest, and preserve exact
references. No currently unadopted fixture profile becomes an official snapshot
schema. The full private native schema and genuine provider remain distinct gates.

For native-store-creation in the new journal, its typed admitted per-store intent
must precede and parent the generic intent. A bare generic scope4 intent refuses
immediately. Maintain bounded per-store/per-reservation state, not one global
store boolean. No permission, typed parent or store provenance may be inferred
from a generic effect scope, reservation hash or later confirmation.
