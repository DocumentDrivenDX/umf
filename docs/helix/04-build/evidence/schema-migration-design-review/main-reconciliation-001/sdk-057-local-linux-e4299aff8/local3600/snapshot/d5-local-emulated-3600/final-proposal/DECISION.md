# LOCAL_EMULATED_3600 D5 operator proposal

This is a source-only proposal for one new local Linux emulation qualification run. It does not modify the UMF checkout, original proposal at `/private/tmp/migration-d5-local-linux`, the original workflow, or any D5 case/oracle implementation. No candidate, Docker container, test, Git command, or Actions workflow was run for this proposal.

The adopted local operator resource policy raises only the whole-suite aggregate ceiling to 3,600 seconds. Its work clamp is 3,530 seconds, retaining the 60-second evidence reserve and 10-second kill grace. The 180-second per-command cap and all other scope and limits remain fixed: 30 ordered commands, 37 cases, 16 oracle groups, 19 no-default checks, three fault scenarios, 180 child bound, 1 MiB raw logs, 16 MiB evidence, and 2 MiB payload. Product/API budgets and production-host semantics are unchanged. The profile is explicitly `LOCAL_EMULATED_3600`, reports local diagnostic evidence, and carries the profile and operator-source hashes into the child qualification inputs, local result receipt, and outer Docker-context receipt.

The three extracted source workflow steps are byte-identical to the original proposal and retain their frozen source hashes. The three local adapter steps change only aggregate deadline inputs, local profile/hash identity, and finalizer aggregate acceptance. The driver enforces the new profile, wraps the complete client-container run in a 3,600-second watchdog, and captures outer stdout/stderr separately with 128 KiB per-stream caps and full-stream digests; a truncation marker consumes space inside each cap and any truncation or capture failure returns nonzero. The 1 MiB raw-log budget is explicitly split into 768 KiB for child logs and 256 KiB for outer logs, then counted together. The physical selected-evidence receipt inventories the entire bounded regular child `d5/upload` tree, including replay custody, fixed evidence, all 30 command logs and the full 22-report roster. It rejects symlinks and special files, verifies exact route log names, and counts child logs once. It separately binds outer capture and streams, operator inputs, source workflow and attestations, plus the exact three-file release payload. Its `roots` map explicitly binds output, proposal operator/attestation, and pinned source roots. The receipt digest is bound by context, with the context's final byte count included in the receipt through a fixed-point closure; total selected bytes are rechecked against 16 MiB. The trap first proves the Docker daemon is reachable, removes only the uniquely named client container, PostgreSQL container, and private network, then verifies successful exact-name filtered listings are empty for those owned names. Daemon loss or any listing error leaves cleanup unverified and makes the driver fail.

This proposal fixes both outer and child attempt identifiers at attempt 1 for a fresh `LOCAL_EMULATED_3600` profile run; it does not reuse attempt 2 from prior evidence.

The earlier original-profile 1,800-second attempt at `/private/tmp/migration-d5-e4299aff8-002/` remains a failed/unqualified attempt. Its 37/19 coverage and fenced-resume evidence are preserved, while two fault rows remained unclosed as FAIL_OR_UNKNOWN and the final audit stayed unqualified; this is not a claim that the underlying fault semantics failed. This proposal does not reinterpret that result or stitch it into a new run. A future authorized fresh run must independently close all 37 cases and all three fault scenarios under this profile before it can support a `LOCAL_EMULATED_3600` semantic qualification claim. It cannot claim the original 1,800-second gate or hosted qualification.

`unified.diff` contains focused diffs against the original operator proposal for the changed files. `frozen-source-hashes.json` records the original and proposed source roster and explicitly records the unchanged workflow-step hashes. `resource-profile.json` is the separately named policy object; its digest is pinned by `local-adapter-manifest.json` and included in receipts.
