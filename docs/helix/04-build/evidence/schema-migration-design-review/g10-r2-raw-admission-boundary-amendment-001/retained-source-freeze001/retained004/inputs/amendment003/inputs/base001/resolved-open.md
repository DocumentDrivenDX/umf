# Design disposition and remaining gates

The proposed interfaces close these design choices: explicit inventory.2 family;
separate unchanged intent/change/marker/operation namespaces; original archived
source/native domain comparison; current after-constraint validation without
data transformation; new-store-only19-table provider; fixed dynamic native heaps
and guard; lossless private PG native send framing;10000-row/8MiB whole-stream
conjunctive limits; immutable lineage with mutable native counters; monotonic
UUID issuance across fresh physical carriers; whole atomic dependency groups;
exact original request/reservation/attempt/outcome/custody registry; single-grant
auxiliary transaction accounting and unknown-COMMIT recovery; independent
conservative elapsed-clock authority; holds, separate signed purge, dependency
census and tombstones; G05 descendant-carrier proof and exact population split.

No further human retention/value/identity policy choice is assumed necessary to
finish this design. The newly proposed version allocations, authority branches,
registry ROOT kind, exact records and renderer must still be reviewed/adopted as
a whole. The table-definition direction is pending its original frozen addendum
pin and must be reconciled before governing adoption; this packet explicitly
states its proposed semantics rather than assuming old public compatibility.

Actual implementation and qualification remain OPEN: original configured fresh
logical/data/clock authority and key custody; new ROOT birth path/kind and durable
CAS/one-grant integration; native provider creation and19-table catalog oracle;
native scalar/send/driver/framing oracles and bounded allocation behavior;
same-original lease/session/core pending/effect guard; enrollment, capture,
baseline, restoration, publication and crash recovery; signed clock/holds/purge
provider; actual G05 descendant capability; immutable Weft original-lineage fill
port agreement, full native program/guard and artifact/session qualification;
old-store migration without OID/ledger/archive adoption; installed0.1→0.2 history
and later old portable-plan integration; complete mixed-table DAG campaigns;
actual generated clients, browser, platforms, installed artifacts, CI and release.

Old-store migration is not designed as an alias, metadata copy or silent refusal
that completes the full goal. The full retained-table and previous G02–G11
acceptance obligations remain OPEN until their actual independently attributable
results exist. Broader native domains outside the finite scalar subset are also
OPEN; their meaning is preserved/refused explicitly, never JSON-coerced away.

The original88 plus new64 cases are obligations, not passed tests. No data-free
record, native-looking dictionary, SHA, fixture OID, source type or design receipt
establishes actual native origin, durability, CAS, COMMIT or installed behavior.
