# R2-IR-F1 — one exact original effect-key derivation

This replaces ONLY the ambiguous purge/hold/policy key derivation in proposal001 lifecycle.md, inherited by amendment003. All full request/intent/native revision/authority checks remain. The same fixed native-free derivation is used by original signer export, core request registry, native/external reservation, replay and readonly lookup. A caller cannot supply a key, scope, specific revision, nonce or requestId as alternative authority.

Validate the COMPLETE closed RecoveryRequest and its selected intent FIRST, including exact integer types (no booleans/floats), mandatory nulls and original target/context/purpose/archive/lineage/custody associations. Then derive the following canonical RFC8785 arrays; there is no generic fallback. Positive revisions below are exact integers1..9007199254740991 and must equal the original protected state at preparation/dispatch. Old terminal lookup replays the SAME original validated request and original outcome without acquiring new action permission.

For retire/restore stepIds is the complete original nonempty selected indivisible group list in canonical plan order; index0 is the ACTUAL first bound step, not sorted by lexical ID or a caller-chosen subset. All other per-kind key normal forms/ID validation retain their original exact meanings.

For purge/hold/policy, lifecycleBinding is non-null; expected lifecycle equals lifecycleBinding.expectedRevision. Purge's two-member final revision vector is ORDERED [policy,hold], never a scalar/min/max/new revision. Both members equal lifecycleBinding.policyRevision/holdRevision and the exact selected native state. Hold expectedHoldRevision equals binding.holdRevision. Policy expectedPolicyRevision equals binding.policyRevision. Every OTHER original binding member, dependenciesDigest, lineageRevision and complete intent/native row check still applies; omission from the key is not omission from admission.

Elapsed purge and minimum-window override use the SAME key for the SAME original prestate. Eligibility.mode, certificate/reason/override data and marker remain in the COMPLETE signed intent/requestDigest. Different eligibility or reason under an occupied slot is a CONFLICT, not a second independent purge opportunity. Override still requires a key enrolled for BOTH purge-retained-table and override-table-minimum-window; payload.scope remains purge-retained-table. There is no RecoveryRequest.kind or alternate effect slot called override. Current exact holds/dependencies/pending/origin checks cannot be overridden.

Likewise hold-add/remove or another holdId at the same expected lifecycle/hold revision use the SAME slot. Different operation/holdId is conflicting intent; a native committed hold mutation increments the real specific and lifecycle revisions before a new action can occupy a new slot. Policy nextPolicy is signed complete intent, not part of a key that could allow parallel alternatives. An expected policy/hold/lifecycle revision cannot be rewritten on retry. A current legitimate new action follows actual terminal/no-effect settlement and a genuine new protected revision as the original contract requires, never a nonce to evade old pending state.

An occupied key admits exact original requestDigest/validated canonical intent and SAME original request/reservation, or refuses. Signature-envelope formatting/re-export is governed by the original signature registry; it does not allocate another effect. Replay performs strict full type/shape/crosslink validation BEFORE equality; Python/JavaScript coercion or boolean/numeric equality must not turn malformed input into exact replay. Source/native/external use ONE function and retain full original request/intent bytes. No key or metadata grants native capability.
