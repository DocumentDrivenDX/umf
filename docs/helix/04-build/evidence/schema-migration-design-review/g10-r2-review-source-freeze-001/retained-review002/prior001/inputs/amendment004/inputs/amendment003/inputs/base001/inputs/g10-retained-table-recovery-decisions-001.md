# G10 R2 retained whole-table recovery decisions 001

Proposed next design, not adopted wire/implementation/native qualification. The
adopted inventory0.1 immediate irreversible purge remains its disclosed first
subset. G05 Field archives and inventory carrier retirement do NOT implement R2
whole-table retention/restore/separate purge. No additional human decision is
needed to plan the following; actual retention duration/holds come from explicit
original host policy, never a default invented by UMF.

## Native values and bounded private archive

Use a separately admitted native whole-table recovery store/profile; do not add
columns/records to old originals-store0.1/0.2 or inventory-store0.1 without a new
closed profile. A private generated values heap has one original instance UUID
plus explicitly mapped stored Fields in their exact admitted native value domains.
Values remain native, not JSON/string/JS-number reconstruction. Capture source
and native column identity explicitly; physical ordinal/name equality is not
logical Field identity. Dynamic archive heaps require actual original born-object
receipts/full catalog and original custody, not a namespace-prefix exception.

The first qualified profile uses the existing admitted G04/G05 scalar/carrier
subset, genuine protected instance identity and native SQL/immutable qualified
provider primitives. No generated/identity/partition/shadow/external carrier is
silently admitted. Explicit signed per-table/per-campaign row/byte/time/statement/
archive-count/storage bounds are conjunctive; use10000 live rows and8MiB complete
private value-stream as initial maximum envelope, with actual host policy tighter.
These are proposed limits, not performance claims. Bound every scan/materialization
before allocation and every original atomic group before effects. Never chunk an
indivisible capture/drop to fit. Preserve actual NULL/native values exactly.

Archive integrity is private: complete original population/ordered instance IDs,
source/native descriptors and lossless typed value-stream proof are retained in
original custody. Any checksum over values stays private; public receipts contain
only original IDs/bindings/counts/bounds, no row values or low-entropy per-value
hashes. Native data integrity/complete-population verification precedes drop and
restore. Full native binary/value codec/count metric/SQL needs exact freeze and
independent oracle; a row count alone is insufficient.

## Restoration and lineage decision

Restoration is explicit from the SAME original archive/source/native authority,
not a `create` with a similar Record or equal physical name. Target must be absent
at dispatch after any SAME-plan separately approved name-conflict removal. Plain
create always means a fresh binding/population and never silently restores values.
Initially restore the original logical table binding/Record/stored Field identity
and exact native value domains; transformations/renames/additional-Field fills
must be explicitly separately adopted compositions. Native after constraints,
RLS/grants/operations/defaults/clients are from the complete selected VALID after
source, not blindly reinstalled obsolete policy. No fabricated source projection
or equal-name Field can replace the original archived definition.

Recreated physical heap gets a NEW genuine carrier token/generation/OID and native
birth receipt. Preserve original hidden instance UUIDs and ORIGINAL LINEAGE through
an explicit separate lineage identity plus immutable parent-generation/archive
links. Do not redefine an old carrier token to mean a new physical object. New
whole-table store explicitly models lineage versus carrier generations, and the
issued-instance ledger is monotonic across ALL generations of that lineage. A
spent UUID cannot become fresh through restore/new heap/token, even for a deleted
original. Old generation/source/epoch capabilities never authorize the new carrier.
Only actual confirmed new generation/ingress/publication issues successor access.

Restore EXACT current-live population captured at table retirement, including
original NULLs. Do not resurrect rows already deleted before capture or replay
original seeds/defaults as data. Recreate/restore population, original lineage
registration, complete target validation, owned dependency activation and actual
native outcome are ONE required group; final source/publication/ingress remains
G10/G11 protocol. Unknown COMMIT resolves SAME original archive/request/target/
carrier generation/receipt, with no second heap, token, values or data replay.
An empty archived table still creates/validates a real original successor object.

Retained Field archives/holds/issued IDs stay reachable across whole-table
retirement and restoration. Original Field captures resolve their original
lineage; an explicitly qualified new provider may target a genuine restored
descendant using original continuity, never by matching bare UUID/new token.
G05 current-population/newInstances semantics still apply: deleted original rows
stay deleted and genuine later instances use their explicit refuse/null/fill
policy. Exact cross-carrier G05 resolver/proof variant is REQUIRED end-state work,
not waived by a successful table-only restore or old Field archive handle.

## Retention, holds, purge and recovery

No automatic purge from schema removal or duration expiry. Minimum retention is
explicit policy ID/revision/duration. Countdown uses genuine qualified original
clock/custody and a conservative actual positive-COMMIT confirmation anchor, not
a predicted future COMMIT time or caller Date.now. Unknown reboot/elapsed/clock/
policy continuity stays fenced. Holds are original authenticated lifecycle state,
not a caller bool. Preserve legal/policy meaning without making legal claims.

Whole-table purge is a separately approved typed destructive lifecycle action
bound to the exact original archive/native values object and current policy/
clock/holds/dependencies. It does not inherit a Field-archive purge signature.
Recheck actual holds/retention and all dependent archive/source/lineage/recovery
uses under an enforceable original lifecycle/target fence through COMMIT. Native
values removal and immutable lifecycle tombstone/outcome are atomic; original
external confirmation follows real COMMIT. Unknown outcome never repeats DROP
or deletes a different same-name object. Keep audit/source/issued-ID/generation/
policy/receipt tombstones after values are purged; tombstones cannot issue restore.

Conservative first dependency rule: no purge while ANY active restore/read lease,
hold or unfulfilled protected dependent Field/table archive recovery requirement
needs these values/population. Do not silently cascade expiry or sever a held
Field archive's only original restoration context. A future dependency release/
substitution must be a genuine positively confirmed lineage/provider operation,
not caller claims that another backup exists. Bound full dependency census; if
uncertain, refuse purge. Already purged values cannot be restored, and metadata
history alone is not backup. Native recovery/source history must explicitly retain
that irreversible state and never create another archive at the original ID.
