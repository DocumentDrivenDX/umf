# Installed SDK G03 browser: compatible Linux tool route

Disposition: use a verified Linux ARM Bun executable in the existing pinned Linux ARM Chromium container, rather than modify/split the source-owned SDK parity script. This is a tool-route plan, not actual tool acquisition or SDK/browser qualification. No tool binary/product execution, network acquisition or source change was performed by Sol.

`scripts/g03-sdk-browser.ts` currently requires Bun.file/write/build/serve as well as Playwright and Chromium. It validates the retained installed @umf/core archive/public-entry/member custody, builds only from that installed public package, checks all bundle input hashes/no external imports, serves the bundle/corpus on loopback, executes real Chromium and compares the paired Python corpus report. Node alone cannot run these Bun APIs. A builder-side prebundle alone also cannot run the unchanged script because its Bun server and custody/build checks still execute in the host process. Splitting the script would enlarge the source and provenance changes unnecessarily.

The existing actual amd64 builder has Bun 1.4.3 and no selected Chromium; existing ARM Chromium image `sha256:eff16c30e6f3f4af0a03fa4b706120d5e9b0891c344a27d64559aff5900a4a27` has Node v24.20.0 and no Bun according to retained metadata. Its actual Chromium is 153.0.8010.12 at `/ms-playwright/chromium-1243/chrome-linux-arm64/chrome`, SHA-256 `839efe5fd8b6a773dd81b2e10afdc15f3c0a17316fb82b5908c0533306c4ed9e`. Do not execute the amd64 Bun binary in this ARM image or assume an existing compatible Bun path.

Root/Luna should first locate an already retained official Linux ARM Bun artifact at the actual selected SDK producer's Bun version, or acquire that same version through a separately bounded official release download. Current retained builder metadata is Bun1.4.3; UMF packageManager declares Bun1.4.2, so record the deliberate actual selected tool version instead of silently changing the package declaration or inventing equivalence. Preserve whichever version the actual SDK operator contract selects; do not upgrade it as a browser workaround.

Before candidate execution, retain official release/asset identity and archive URL, measured byte size and full archive SHA, safe closed extraction/member path, executable size/full SHA/mode, actual ELF AArch64 architecture and any interpreter/library requirements as data. The actual binary/digests are unknown to this plan and must not be filled from guesses. Mount only the selected executable/tool tree read-only into the unchanged pinned ARM browser image. Run bounded Linux-only tool metadata (`--version`, exact executable hash and loader availability as needed) under network-none before admission. A missing loader or incompatible version is a held tool precondition, not permission to install arbitrary dependencies or use an unpinned fallback. No Mac executable/installation/runtime action is required.

Run the unchanged SDK browser script using that Bun, a read-only UMF source, exact current corpus and paired embedded Python report, actual retained SDK archive and consumer install/custody directory. Mount the actual archive and install directory at the absolute paths recorded in `g03-sdk-install-custody.json`; the script compares those strings, archive hash, installer-source hash and exact installed/archive member identities. Preserve the actual selected source cwd because it reads package.json and its source-hash roster by relative path. Ensure the static `playwright` import resolves the reviewed portable JavaScript package pair inside that cwd; do not rely on a host Darwin dependency tree or silently substitute package versions. Retain their complete file rosters/hashes. Only fresh scratch and a bounded report destination may be writable.

Keep Chromium executable/version/hash, original parity and package-closure checks, no external browser requests, network-none container (loopback server only), installed139 custody requirement, all corpus counts/refusals/tamper checks, resource and evidence limits unchanged. Do not run `test:sdk` or rebuild the SDK as an installation shortcut. The Bun host process is Linux ARM; the browser receives browser-target JavaScript and must still expose neither Bun nor process. The route needs its actual source/capture/tool/input pins reviewed before root executes it, and its real resulting parity report reviewed afterward. No Actions, Mac runtime, native authority, release or Praxis claim follows from selecting this tool route.
