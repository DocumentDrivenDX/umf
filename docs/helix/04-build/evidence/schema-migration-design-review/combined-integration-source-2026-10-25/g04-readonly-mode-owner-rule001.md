# G04 readonly settlement: mode-aware owner rule

Original signed creation evidence is immutable provenance, not a demand that a later recovery transaction be writable. Keep its bytes/digest unchanged and verify them against the same original scope4 request, approval, registration, authority receipt, target custody, configuration, reservation and pending/confirmed Core state. No new public profile/signature scope is needed.

Use a closed private invocation distinction derived ONLY from the registered creation budget or registered readonly-recovery budget. Do not accept a caller mode flag. Creation continues to require off. Readonly recovery requires actual transactionReadOnly=on, READ COMMITTED, pg_catalog search_path, UTC, row_security=on, session_replication_role=origin and the original maintenance/session/controller identities.

Comparison is explicit: every signed creation-evidence member is equal except requiredSettings and nativeAuthorityObservationDigest. requiredSettings compares each key exactly except its transactionReadOnly changes off→on in the NEW actual recovery observation. The signed original member remains off. Compare supervisor/custodian/provider/installation/authority/policy/registration/custody/principal OID+name+flags/membership facts exactly. Actual process/launch continuity follows the existing original-origin chain, not equality to an obsolete launch. Original nativeAuthorityObservationDigest remains an original reference; current observation/digest are freshly computed from actual on settings. Likewise recompute current privilegeClosureDigest from current actual rows/settings; compare underlying stable principal/membership facts rather than requiring equal hashes across different sessions. Never fabricate off, copy old observation bytes as current, or issue creation authority from the recovery record.

This is not permission to ignore settingsDigest. Validate COMPLETE current pg_settings through the fixed original source/configuration profile, retaining actual rows/count/digest; only the named readonly transaction mode and statement_timeout/lock_timeout/qualified driver waits may differ. Timeout values must be positive and no greater than remaining recovery allowance, fixed host maxima and any genuinely established lower original bound; zero original timeout means unlimited, not a zero permitted wait. Any other source/value/pending_restart/config/HBA/role drift refuses. A hash alone cannot prove nonallowlisted row equality: if a route requires exact original full-row comparison, retain/resolve that original authenticated row preimage, or refuse that stronger claim rather than normalizing a digest.

Thread the SAME readonly_budget through _native_store_preparation_payload (~5014), _connect_maintenance, every principal/membership query and fetch, _observe_native, and _native_origin_matches’ supplemental reads. Split _store_required_settings (~5160) into exact creation and exact recovery predicates. Do not call the creation-only _resolve_original_store_preparation path to validate recovery: it currently opens writable/unbudgeted observations and compares whole evidence (~6330). Keep original evidence validation separate from current recovery-session checks, returning a private checked recovery observation rather than a forged creation-evidence payload.

Bootstrap rule: _BudgetedOriginalStoreReadonlyConnection.__init__ must NOT execute its initial pg_settings query before finite limits exist. Prefer a supervisor-owned fresh recovery connection whose existing qualified startup configuration supplies finite statement/lock waits and connect timeout before FIRST SQL/BEGIN. Mint/bind the30s/0-DDL invocation to exact original journal/Core identity before connect. Pass the authenticated startup lower bounds into the private wrapper; then query/revalidate actual limits and only tighten. Never source them from a DTO, use an arbitrary supplied connection, raise an existing known lower cap, or treat a monotonic precheck as cancellation of a blocking query. If the actual qualified connector has no finite startup source yet, implement that concrete startup path (or a qualified deadline-bounded driver discovery call) before enabling it; an unbounded discovery fallback is invalid. This names a required implementation seam, not a permanent blanket refusal.

Recovery allowance begins per invocation and cannot replenish creation’s original30s/2-dispatch budget. It permits bounded observation/original journal/Core settlement only, never DDL or retry dispatch. Controls remain UNRUN: genuine readonly same-original committed settlement succeeds; actual on/current digest retained; wrong principal/membership/config/settings refuses; lower waits preserved; first-query timeout established; every supplemental query shares budget; exhausted/unknown state stays fenced; no SQL/DDL authority from mode or observed hashes.
