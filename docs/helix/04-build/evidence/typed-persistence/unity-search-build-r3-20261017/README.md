# Unity search build bridge evidence

The actual browser-compatible schema generator produces the source-bound
`search_docs` package from the retained original model. The public SDK catalog
CLI then builds ANN and target-defined HYBRID catalogs using the isolated R3
compiler, and `--check` confirms exact regenerated catalog bytes. HYBRID retains
the same original `q` argument in its current-row filter and text query through
distinct internal compiler slots. Original native SQL and REST bodies remain
owned by Weft.

The actual compiler review controls refuse captured keyword substitution and
retain arguments whose original names resemble internal slots. Eight focused
build/runtime unit controls cover those faults, unavailable index readiness,
rank preservation, stale rows without refill, native denials, changed closing
identities and corrupt candidate inventories. Unit transports are test doubles;
these controls do not establish native cloud acceptance.

[Compiler pins](compiler-pins.json), [CLI check](catalog-check-r2.log),
[bridge controls](sdk-unity-build-r3-review-controls.json) and
[independent follow-up](sdk-unity-review-r3-followup.json) retain the scoped
results. The first CLI attempt failed because the harness imported `Vector`
from the DSL module instead of its public runtime export; that original log is
retained, and the corrected public import passes. This is source-mode SDK
evidence with a real installed compiler, not a final installed SDK-wheel gate.

Managed index operations, independent native authorization, exact table
admission, native hydration and whole-call deadlines still require the real
managed fixture campaign. Temporal qualification remains HELD. The
[inventory](inventory.json) binds retained raw files for diagnostic custody.
