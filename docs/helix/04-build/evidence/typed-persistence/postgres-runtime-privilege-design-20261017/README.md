# PostgreSQL SDK runtime privilege inventory design

Temporal is **HELD**. This is a source inventory and executable-resolution design, **not** a qualified least-privilege grant set. The production privilege report remains incomplete. Exact fixed SQL text, call-site lines, source hashes and direct function signatures are retained in `source-inventory.json`; 12 distinct runtime statements are accounted. The local PostgreSQL18 bootstrap file supplies signature provenance, not proof of native ACLs.

Plain verify/read/page/stream share role, relation, column, selected-Key and search-path checks. Each executed statement also refreshes statement_timeout. Explicit schemaBinding additionally selects database/system/path/relation identity and complete native shape fingerprint SQL. A cold shape path executes columns/Keys; a warm hit still observes roles, table identity, locks, resolution and fingerprints. Closing read/page checks repeat compiler admissions, resolution, shape and role before returning rows. Eager verify returns at the verified event and does not execute business/closing statements. Streams hold one read-only REPEATABLE READ transaction and repeat page checks; async uses the same SQL templates. `targets.py` and `verification.py` add host checks/cache operations, not SQL.

Twelve direct function overloads have precise pg_catalog bootstrap identities: set_config(text,text,bool), pg_has_role(name,oid,text), unnest(anyarray), jsonb_build_object(variadic any), jsonb_build_array(variadic any), jsonb_agg(anyelement), to_jsonb(anyelement), current_database(), current_schemas(bool), pg_control_system(), quote_ident(text), to_regclass(text). These are scoped per original template. JSON aggregate helpers are listed separately. No broad EXECUTE proposal follows from this list.

The shape fingerprint intentionally serializes complete rows of pg_type, pg_collation, pg_inherits, pg_index, pg_opclass, pg_opfamily, pg_amop and pg_am. Whole-row SELECT is explicit with PG18 column expansion; pretending only visibly named columns are accessed would be incorrect. pg_roles is a view: do not turn its owner-mediated pg_authid expansion into a caller pg_authid grant.

The finite operator candidate set is deliberately **not** an exact resolved overload list or a grant proposal. The native-resolution plan resolves unchanged templates via pg_rewrite.ev_action, including pinned builtins, sort/aggregate/cast/subscript dependencies and protocol-adaptive int2/int4/int8 OID variants. Type I/O and internal operator/aggregate implementations are distinguished from direct SQL EXECUTE ACL requirements. Every unresolved expression has a closed resolution route; unknown native execution nodes refuse closure.

Original business/LOCK/native-admission programs remain Weft-owned and separately incomplete. Search uses shared read admission plus its retained search programs and listed fixed search control SQL. Actions add serializable transaction/recovery and pg_xact_status(xid8), plus original action control/receipt/reconnect programs; these extras are retained separately and not included in the plain-read grant set. Native principal grant/revoke proof, overall compiler closure and least-privilege qualification are still pending.
