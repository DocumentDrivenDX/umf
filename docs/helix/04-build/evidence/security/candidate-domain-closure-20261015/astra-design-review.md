This is a design review of baseline 6afddd95, not an implemented program, authority credential, compiler admission, or S24/S25 qualification. The proposed obligations below must enter the owning contract before new meaning is implemented. The existing original 0.1 API and deliberately narrow 0.2 legacy bridge must retain their qualified behavior.

1. Compile one original source packet.

Capture policy, ontology, catalog, core document/revision closure and the operation-owner profile together into detached bounded JSON. Validate the canonical security-v0.2 schema; preserve original 0.2 bytes/values rather than rewriting them to 0.1. Close every known reference, rule ID/action/target, classification, selected Key, lexical variable occurrence, scalar domain, and catalog disclosure. Policy->ontology and policy->catalog pins must be exact; ontology document pins and the supplied catalog core closure must describe the same captured documents wherever they overlap, with no conflicting duplicate. Prefer one explicit complete document closure instead of two independently supplied same-revision bodies. Exact declared pins and private issued handles establish correspondence only, not authenticity.

The old candidate policy checker still imports the historical prototype policy schema and unconditionally treats a transformed disposition as an inline constant with value. Replacing its schema import alone is insufficient. Separate inline legacy constants from catalog reference directives, resolving the latter through existing original source/domain/parameter/obligation checks. Reject unknown source members, unresolved residual terms, unknown required meaning and mismatched selected input/output Fields before constructing any executable logical program. Opaque .native archives remain preserved and never execute.

2. Preserve scalar domains and ownership.

Use an index over every exact core Field in the closure for typed constants, output-domain DTO Fields, catalog parameters and explicitly allowlisted context Fields. These references do not assert live Record ownership. Subject/resource/witness attribute terms must still belong to their exact selected Record. A context Field must be named in ontology.context and obtain its value only from the captured host context; it does not become a Record member. Keep original supported scalar families/cardinality/refinements and explicit decimal precision/scale. Nullable/absent-allowed attributes and output constants must not silently become unsupported merely because the old candidate helper required every scalar to be required. Selected identity Keys and member-backed endpoint key components remain required and use the original ordered key codec.

Known typed null is a value, distinct from missing/known-absent. Preserve original equality, including null-versus-null equality where the original typed contract admits it; do not import SQL NULL rules. Missing required provider coverage or omitted required values refuses before boolean evaluation, even under a constant-false branch. Explicit known absence may yield U in a value comparison, while composed-original absence still satisfies the write read-protection guard. Scalar domain equality uses the original domain contract; identity equality additionally includes qualified Record and selected Key, never raw tuple bytes alone.

3. Reuse occurrence-bound typed condition semantics.

Factor the existing candidate resolver and expression normalizer into an issued compact program: one captured root closure, typed domain/key/association tables, and per-rule/target condition IR referencing those tables. Retain fresh occurrence IDs for each exists binding, not alias strings or selected association alone. The same occurrence supplies both endpoints, witness identity and witness attributes. Refuse variable shadowing, escaped/cross-scope handles, copied/unissued programs and forged transport descriptors; reconstruct/recheck any transported source before execution. Private handle provenance does not authenticate an owner.

The source language remains literal/eq/and/or/not/exists over its original member-backed and directed singular graph selectors. Do not add recursive paths, counts, query compilation, dynamic property names, inferred relationship Fields, or unsupported qualifier interpretations. Existence uses strong Kleene aggregation: a T witness gives T; otherwise any U gives U; an admitted complete empty relation gives F. At the action decision layer, any scoped-rule U gives indeterminate; otherwise require at least one true permit, every require true, and every forbid false. Evaluate only matching action/target groups; an empty group denies. All branches' dependencies are admitted before short-circuiting truth is considered.

4. Define an explicit graph fact-cut carrier.

Retain original Record facts (qualified type, ordered selected-Key values, field/value entries and explicit absence), one selected Subject, requested resources, typed context and original generation comparison. Add separately tagged qualified relationship incidences; do not encode graph endpoints as invented member Fields. Each incidence contains exactly the selected roles and ordered endpoint Key tuples. The program supplies each role's exact target type/Key and source/target side; input must agree with that declaration. A record-key witness names the exact selected association Record key and resolves its attributes from its own captured Record projection. An opaque-existential witness has only its per-cut/per-occurrence endpoint-bearing row; no public native ID, identity term, attributes, cross-occurrence equality, count, distinct or disclosure capability is invented.

Relationship coverage must independently attest completeness and all required endpoint/witness-attribute projections. Endpoint Record coverage alone does not establish an empty relationship inventory. Keep occurrence enumeration and required field admission separate. A row cannot borrow an active flag or an endpoint from another witness. Reject conflicting projections of one qualified Record key, duplicate keyed witness incidence identities with conflicting endpoints, wrong role/type/Key/order, and missing required witness data. State explicitly whether repeated identical keyed rows are forbidden; preserve the original fact uniqueness contract. Do not reject or collapse parallel opaque edges merely because their endpoints are equal: endpoint equality does not identify a bare witness. Preserve their input occurrences for correlation and resource accounting without exposing stable identity. Endpoint identity itself does not synthesize an attribute-bearing target Record or prove native referential integrity; physical incidence/coverage custody remains the provider's separate obligation.

5. Compose logical dispositions without fabricating values.

Only true permits contribute declarations. Withheld dominates. Original does not override a transform. Protected selected Fields without an applicable declaration are indeterminate; explicitly unprotected Fields alone default to original. Inline constant equivalence keeps original typed literal normalization and qualified output Field. Catalog directives retain exact catalog pin, transform id/version, input and output refs and original declaration provenance. Repeated identical directives can denote one selected transform; differing directives conflict unless the owner defines and qualifies a composition. Do not equate different transforms because one sample output happens to match. Preserve conflict and original/withheld/transformed distinctions atomically.

A logical write guard may know that a closed catalog directive is nonoriginal without executing its value function, key or vault operation. Expose that capability explicitly: logical disposition/action evaluation is not transform execution, value projection, algorithm enforcement, custody satisfaction or general requireProtectionInterpretation admission. Unknown/malformed directives still refuse. Read/blind OR semantics may skip an unneeded read-result computation after a real blind grant, but cannot bypass source/type/profile validation.

6. Complete the operation-owner profile.

Require a versioned source-owned complete write profile. readAction must match declared read purpose; each normal field-action mapping must match field purpose. The separately owner-mapped blind action is field-only (not read+field), distinct from all ordinary read/CRUD/field/ownership/policy IDs in the same profile; field-only purpose never supplies its mapping or grant. Ordinary read+field combinations remain valid outside that special slot. Retain existing owner rules for CRUD/ownership/policy IDs instead of inventing a purpose or relabeling them other/reverse/vault-write. Vault actions must be exact vault-write-only. Weft retains sole originalAction query designation; this program must not create a competing query profile. Exhaustive declarations and these comparisons still do not prove global route/source/owner authenticity.

Every target Field needs explicit canonical or stored-transformed storage classification. A catalog-declared stored output cannot silently become canonical through omission or downgrade. For stored Fields, bind the exact owner-selected storage transform (including catalog pin); its outputDomain is the canonical stored Field. Multiple transforms sharing that output require explicit selection, not first-match inference. A presentation transform cannot substitute for the storage binding. Mutation requires the exact declared vaultWriteAction evaluated on that resource in each selected state, in addition to normal mutation and original-read-or-blind permission. Read/original-authorized/reverse or another vault action never substitute. Missing vault declaration refuses mutation. No vault/key execution or plaintext recovery follows from this logical permission check.

7. Preserve full write-state checks.

Create checks proposed state; delete original; update both. Reuse the original exact typed changed-value and subject/context/generation comparisons, including canonical no-op equality, original null and known absence. Ownership selectors must discriminate member-backed Record associations from core Relationship refs. Compare before/after graph incidence inventories as well as Record facts. Changes outside explicitly allowed ownership inventories refuse; allowed changes require existing ownership and policy actions in all selected states. Preserve opaque incidence multiplicity as captured inventory for this conservative comparison without treating it as an exposed semantic identity/count operator. Never compare only endpoint sets or JSON numeric spellings. The same complete admitted program/source/profile must apply to both states.

8. Bound the actual work before expansion.

Capture input with the original JSON bounds and private aggregate key/string ledger. Precharge source validation work, repeated core refinements/allowedValues/numeric expansion, association/entity validation, rule-target incidences, and typed IR expansion before entering helpers that clone whole roots. The current candidate transport duplicates complete sources per target/condition; source-node limits alone do not bound that multiplication. Retain one closure and compact indices where possible. Runtime ledger includes cut validation, original key/literal operations, existential row visits, nested loops, action/read/blind/vault evaluations, disposition contributions and both update states. Validate each original budget before minimum/division; do not reset per branch/action/state. Refuse atomically on any exhaustion with no partial logical result. Distinguish retained/work limits from total parser, validator, allocator or native CPU/heap guarantees.

Required independent acceptance remains more than source acceptance: execute real catalog-bearing policies over both association representations; cover same/different/self endpoints, compound keys, same-label foreign types, split-witness counterexamples, nested/sibling bindings, complete empty versus incomplete relations, nullable/DTO/context domains, every K3 rule effect and true-permit mask precedence. S24 must include original/null/absence, withheld, transformed-null/changed-domain and equal-mask mutation, no grant/wrong Field/unknown branch and both states. S25 needs exact storage binding and actual vault permission positives plus missing/wrong/read/reverse/unrelated vault grants, canonical downgrade, all-state and graph-authority mutation refusals. Replay unchanged independently authored expectations in Bun and Chromium, with source/budget mutation controls. No full S24/S25 or native case promotion follows from the typing prerequisite alone.
