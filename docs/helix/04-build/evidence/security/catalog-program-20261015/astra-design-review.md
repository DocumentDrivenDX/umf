# Canonical security 0.2 compiler: scoped review requirements

Baseline: `7a94067835dcdb4c6c39b01660f16c88c329a6d4`. This reviews a proposed private logical compiler, not runtime authorization, general protection execution, S24/S25 acceptance or native admission.

The proposed direct definition-index path is appropriate. It must reuse the actual pure recipe checker; introducing synthetic policy rules/disclosures would blur source binding and fail to validate unused definitions. The current in-progress `functions.ts` implementation keeps its `definitionContext` module-private, constructs it from actual parameter validation, and shares its budget and Field index. A source-shaped result supplied by a caller must never replace that construction in the compiler.

## Required issuance gates

1. Capture one detached source packet before validation or selection. Bind exact canonical policy version, ontology identity/revision, catalog identity/revision where present, and the complete core pin/document bijection. All overlap must name the same captured core bodies. Retain opaque native payloads without interpreting them; refuse unknown semantic members/versions, incomplete core meaning and residual conditions. Preserve a genuine no-protection policy branch rather than inventing a placeholder catalog.
2. Validate every declared catalog parameter and bucket literal, then every pure mask/generalize definition, including unused definitions and definitions referenced only by false conditions. Share one original literal budget across these stages. Reuse one Field index. Known but unsupported regex recipes refuse; no fallback to a generic opaque pure function. Exact date profile, decimal facets, parameter names/arity/families, positive bucket width and scalar bounds remain the existing function checker's obligations.
3. Non-pure hash/token/encrypt definitions remain nonexecuting declarations. They still require the actual whole-catalog obligation checker, complete exact action-purpose closure, correct reverse/vault roles, hash algorithm/salt/equality warning and all propagation declarations. A report marked unverified is neither permission nor native/key/vault custody.
4. A reference-ready pure definition means signature/domain applicability. Input-dependent output refinements can still fail at execution. Do not label the compiled recipe total or assert property facts merely because signature validation succeeds.
5. Check every rule/target instance against the original issued ontology root. Rule IDs, action lists, target refs, disclosure inputs and output references must be exact and nonduplicated as required. Require/forbid rules must not carry ignored disclosures. Every live disclosure input belongs to every selected target; DTO Fields remain legal only in their domain/constant/context roles. For selected catalog directives, the original disclosure input and output must match all components of the transform input/output references.
6. Use original normalized conditions with complete source and association correspondence; preserve lexical occurrence IDs, native graph side/role meaning, Record witnesses versus opaque witnesses, and exact qualified identity domains. Compact conditions must remain bound to the exact ordered issued association table and original entity scope. A private program WeakMap is implementation custody, not an authentication token.
7. Precharge the full source/entity/association validation and rule-target/expression expansion before entering repeating helpers. Empty or unused associations still cost work because the existing normalizer checks them. The current normalizer also builds source Field maps/canonical body comparisons per available association. Count this cost or share the original indexed work; a source AST-node count alone does not bound that expansion. Preserve the stated limits of post-copy ledgers rather than making a total CPU/heap claim.
8. On any late definition, rule, scope, budget or source failure, issue no program and expose no partial compiled table as usable. Retained original source/diagnostics may remain inspectable. Inputs and previously issued programs must not change when caller-owned source objects later mutate.

## Independent control matrix for the forthcoming factory

- Positive programs: genuine no-catalog inline constants; pure catalog constant/null-out/partial/fixed-redact/prefix/bucket/date signatures; independently authored DTO output/context; nullable live attributes; record-member association conditions; graph Record-key and opaque endpoint conditions; permit/require/forbid rules with every rule target typed.
- Whole-catalog refusals: valid used definition plus invalid unused definition; empty rule list plus invalid definition; false condition plus invalid definition; unsupported regex; late bad parameter/refinement; known required output receiving null; missing decimal facets; invalid date profile; aggregate parameter-plus-recipe budget exhaustion. A valid definition that may fail on some concrete output remains signature-ready, with no total output claim.
- Obligation refusals: omitted purpose taxonomy, undeclared policy action, read/field alias as reverse or vault-write, incomplete propagation, missing hash algorithm/salt, nonreversing transform with reverse action. A valid non-pure declaration compiles only as nonexecuting unverified metadata.
- Source/type refusals: stale policy/catalog/core pins, duplicate identities, foreign/missing/non-Field references, unknown member/version, equal-family wrong qualified Field, wrong target ownership, nullable Key, unlisted context, incompatible domains, copied/unissued root/condition, same-looking but different source body, residual condition, unsupported graph witness identity/attribute.
- Expansion/bounds: exact and one-over source/rule/target/node limits; small AST multiplied across many targets; many available unused associations; all parameter checks plus every pure signature consume one shared budget. Invalid limits or numeric coercions must not widen the selected budget.
- Snapshot and process custody: caller mutation after compilation; immutable retained sources/tables; copied JSON program refused; cross-program scope/table swapping refused; accessor non-entry where existing JSON boundary promises it; actual Bun/Chromium output parity and no host/global/native calls.
- Regression: unchanged public pure function API outputs/refusals under the independently authored 460-vector oracle; genuine old candidate transport regeneration and no general 0.2 interpretation gate opening.

## Still required after this compiler

Actual Record and graph fact/coverage supply; strong-Kleene condition evaluation; permit/require/forbid action evaluation; true-permit disposition composition; exact effective original-read and independently granted blind-write guards; exhaustive Field storage classification; exact selected stored transform and vault-write action; before/after graph incidence comparison; all operation states and shared runtime budget. Different catalog transform IDs must not become equal merely because a sample output happens to match. Original compiler/profile/source authenticity and protected native release remain separate.
