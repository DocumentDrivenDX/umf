# Candidate stored-query source inspection design

Proceed: the proposed private inspector faithfully resolves the conditional stored-source gap if it consumes the original issued catalog program and a detached complete logical-owner source, selecting the actual (type, Field)->storageTransform->outputDomain chain. It must never synthesize a transformed policy disposition. This closes only source resolution/property comparison; the existing Weft-owned query producer, actual dependency lineage, native mixed-mode dispatch and P03 admission remain open.

With no action/cut input, the inspector cannot establish an effective ORIGINAL read disposition. A canonical stored Field may be withheld or transformed by a selected read policy. Resolve its storage meaning irrespective of policy grant, return false authority/completeness, and neither invent nor require a read permission. Its canonical query domain is the stored output Field; the clear pre-storage input domain remains separate retained metadata.

Required validation:
- Original WeakMap-issued program handle only; copied, forged or foreign handles refuse. Unpinned/null catalog refuses stored selection.
- Capture owner and selection once into private immutable JSON, with closed exact versioned shapes, existing bounds and source preservation on refusal. Optional owner.disclosure must be validated consistently if full owner parity is claimed.
- Validate the entire exhaustive storage map against all live ontology entity Fields, including unrelated entries: exact qualified type/Field membership, duplicates, omitted Fields, unknown entries, canonical downgrade and exact id/version/custody storageEffect. DTO-only output Fields are not automatically live entity members.
- Selected storage must be stored-transformed, tokenize/encrypt, and exactly match outputDomain. Keep Field/type components unambiguous. Explicit owner choice may disambiguate shared output domains; never choose the first catalog match. Prefer one private validator shared with the existing action kernel.
- Extract the current property algebra unchanged. Public transformed-disposition behavior, statuses, diagnostics, omitted-mode prohibition, mandatory join/group/order properties, typed range identity and random-token join/group refusal remain intact.
- Reuse the issued program's immutable validated sources, but create a fresh private operation budget. Do not reuse the compiler's exhausted literal ledger or accept a caller checker/budget. Meter owner/catalog scans and property/literal normalization under bounded totals; snapshot bounds are not a total allocation/CPU theorem.
- Retain owner, selection, program sources/pins, selected transform, canonical output domain and authored/implied/effective/required/missing properties distinctly. On unresolved input, clear resolution coordinates atomically while retaining captured source/diagnostics.

Independent controls required after implementation:
1. Genuine token and encrypt selection; original policy bytes/version retained without a synthesized read transform. Read denied/withheld does not become a permit through inspection.
2. Copied/forged handles; missing catalog; unknown exact members/operator; empty/oversized required array; source/selection mutation after capture; original input unchanged.
3. Same-local-name wrong document/module/type; DTO-only Field; missing/duplicate unrelated storage entries; canonical downgrade; stale transform version/wrong output/custody; alternate explicit same-output transform selection.
4. Omitted queryUse prohibited; original-authorized remains requires-original-action; random-token join/group refuses even authored equality; deterministic unauthored equality reported as implied without claiming P03 acknowledgment.
5. Complete public-helper differential regression and exact parameter/range identity behavior; shared resource exhaustion cannot reset between scan/parameter/property stages; browser parity for the private portable module.

Single-Field property inspection cannot establish two-operand key/provider equivalence. Actual fixed key scope, concrete function facts, compiler-derived predicate/aggregate dependencies, explicit equality acknowledgment where P03 requires it and source authenticity remain higher-owner obligations. No root API export, native execution, tokenization/reversal, SQL compiler or acceptance promotion follows.

This is design review only. Baseline pins are committed HEAD bytes; concurrent uncommitted query-kernel/contract edits are deliberately not implementation-approved by this record.
