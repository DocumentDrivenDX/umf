# Metamodel authority execution evidence

The [completion plan](../../metamodel-authority-plan.md) owns execution gates.
Evidence here is scoped; no complete implementation or deployment is claimed.

- `baseline/`:139 original observations spanning historical/current envelopes,
  exact original source hashes and Python's actual unsupported/incomplete subset.
- `baseline-current/`: separate139 composite0.10 cases,51 valid/88 invalid,
  captured before replacement from an isolated `git archive` of
  `19fe5f1bc98840e3177e0d05584321c1e274bfdd`. The one-time capture tool verifies
  every original pinned source hash. Each case retains original identity/version/
  document hash and explicitly records its top-marker-only test construction.
  This construction makes no native migration/equivalence claim.
- `initial-parity/`: initial generated implementation matches all139 complete
  current validation outcomes with real Registry, including ordered diagnostics.
  Isolated key/relationship comparison also matches122 structurally admitted
  cases;17 structural rejections do not enter the semantic program. Temporary
  phase verification used an empty Registry stub and is qualified accordingly.
  Runner copies are inert text, never active runtime or authority inputs.
- [Reviewed corrections](corrections.md): explicit current-entry and completeness
  changes requiring their own before/after vectors and final regression.
- `corrected-parity/`: all139 outcomes compared after the explicitly approved
  completeness correction, with before/after source hashes and exact ordered
  diagnostics. Later implementation changes require renewed final proof.
- `browser/`: generated validators exercised in Chromium under strict CSP,
  including the real Registry Boolean-schema callback. Consult the receipt for
  exact source hashes and browser identity; arbitrary object-schema compilation
  remains a separate capability.
- `current-fixtures/`: original fixture bytes and explicit migration deltas.
  Native codec, receipt and vocabulary identities retain their own versions.
- `history/`: original retired-source evidence. A preserved copy alone does not
  justify deleting useful current behavior tests; the final retirement ledger
  must identify their active replacements. These files are excluded from shipped
  package and site inventories.

Original and supplemental captures used Bun1.4.3; historical Python observation
used Python3.13.16. These captures qualify those environments. Final compiler,
installed Python, Chromium, native, distribution and release proofs must state
their exact producer/source/runtime identities independently.

`capture-tools/` retains byte-exact inert text copies and original path/hash
identities for the one-time capture tools. Their active script paths were removed
after capture, so current generation cannot bootstrap through old validators.
