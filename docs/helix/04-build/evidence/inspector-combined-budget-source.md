## Reachability and eligibility

The index is constructed only in the existing strict ECMAScript, resolved-ref,
finite/unique JSON construction eligibility, plus its internally built metaschema
interpreter. The shared wire constructor can enter that construction scope;
this is not a claim that the scope is exclusive to the retained Python facade.
Generic Schema/Python origin paths retain the qualified unindexed route.

Descriptors contain Root or Catalogue(ordered ordinal), distinct retrieval,
authored and dialect-resolved UTF-16 URIs, root vocabulary declaration and dynamic-anchor facts. Every lookup resolves
against the live immutable owner; persistent addresses are absent. Branch-local
anchor addresses remain the interpreter's original current-owner identities.
Index fast eligibility conservatively requires absolute authored root IDs
when present, UTF-8-readable retrieval identities, and no descendant string IDs
anywhere in the raw JSON tree. Retrieval/authored mismatch does not disable it.
The actual twenty-resource pinned metaschema catalogue includes Draft3/4/6/7
retrieval IDs without a trailing `#` and authored IDs with it; both remain exact.
An opaque annotation containing a descendant string ID selects fallback without
interpreting or deleting it. Relative authored IDs, unsupported depth and
dialect/regex/strictness/origin differences retain the original path. Independent reference/policy/dynamic maps
preserve their different original lookup orders, described below. Surrogate-bearing
schema paths conservatively use the original lookup, retaining whole-path UTF-8
decode/fallback semantics for both valid pairs and lone units. Their guard scan
is precharged separately from origin scanning/comparison. Nested dynamic
anchors retain full original discovery; root-only anchors can use admitted descriptors.

Policy cache storage is one replacement slot per root, not an unbounded map.
It is keyed to the current complete Limits tuple; no host callback occurs under
the Mutex. Explicit local `$schema` wins. Empty diagnostic origins preserve
inherited policy. An owner clone/snapshot clears the index; only the existing
completed-construction copy can share it after its exact input/catalogue/policy
proof. Failed, partial, denied and reentrant constructions publish no new proof.
Root preflight can replace a duplicate catalogue preflight only after the exact
origin and full ordered schema equality under the same owner resolver, limits,
policy and depth. All other catalogue roots, metaschema constraints and fresh
Registry package/identity/scopes/token checks still run.
