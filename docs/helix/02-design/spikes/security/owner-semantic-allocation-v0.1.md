# Owner-issued semantic capability allocation experiment

Draft annex to SPIKE-010 and Weft CONTRACT-005; US-056-AC7/AC10. Original
security0.1 context and fixed owner-record/owner-relational/direct-required-cell
profiles only. Draft graph0.2, native admission and public lowering remain
unqualified. This implements the first issuer prerequisite in
[obligation assignment](obligation-assignment-v0.1.md); it does not issue
required native cases, enforcement sites or obligation kinds.

The existing private checker now retains every complete selected capability
that covers each actual `(scan occurrence, action)` bundle and every capability
that covers the complete application. It returns a private OwnerCoverage only
through an issuer borrowing the original immutable RegisteredSecurityDeclaration
and actual SecurityBackendContext. No constructor or deserializer is public.
The returned object retains both objects and a charged exact selected capability
set, including valid selected capabilities with no covering edge or obligation; it cannot silently move a result to
another same-label context or registration. Borrowing proves custody within
this process, not issuer/source authentication or backend executable identity.

Each scan/action scope retains its whole ruleset and condition measure, including
false branches, nested existential dependencies and all disclosure entries.
Capabilities cannot union partial rule/node/depth limits to cover a scope.
Application coverage independently requires all scan occurrences and ordered
output count under one compatible capability. A capability may cover an
individual action while failing the whole application, or cover the application
while failing an action. Keep these distinct scopes and compose both later.

Return all eligible selected IDs rather than the first matching ID. Selection
order therefore cannot change the assignment relation. Unselected capabilities
never enter it. Existing checks still refuse unsupported/candidate-disallowed
or unknown selected profiles, constraints, target revisions, result domains and
non-direct/nullable outputs. COUNT requirements exist but computed-result
coverage still refuses. Original-authorized actions get their own scopes;
coverage of a zero-rule action does not mean that it Permits any row.

The issuance ledger charges original registration bytes, all prior semantic
traversal, scope-name and candidate-ID bytes before copying, and each retained
scope. Limit the relation to4096 scopes and4096 scope/capability edges. A refused
issuer returns no prefix. The one-million-visit/sixteen-million-UTF8-byte ledger
remains a stated traversal/payload bound, not total CPU/memory or an aggregate
bound across other owner phases. Previously short-circuited successful candidate
matching now examines all selected candidates and charges the entire traversal.

Executable controls use actual owner contexts for independently expected full
and partial candidate sets, reversed selection order, self-join scopes versus
whole-application bounds, separate read/original-authorized action scopes,
immutable registration retained after callback drift, different selected inventories
with identical edges (including a Staff-only empty-obligation capability in a
Resource query), exact measured ledger
limits and one-unit shortages. Primitive retention controls reject empty and
duplicate scopes, exhausted visits and a4097th edge. Earlier source/semantic
regressions run alongside these controls; none is backend acceptance evidence.

Formal allocation laws assume independently correct selected/complete predicates
and exact relation construction. They distinguish all candidates from a first
match, complete-scope coverage from feature union, occurrence/action identity,
application coverage from per-scan coverage and evidence matching from native
execution. Their SAT controls populate nonempty candidate/scope identities.
They do not prove Rust extraction, registration authentication or native
refinement.

The subsequent [source-demand experiment](source-demand-binding-v0.1.md) now
privately binds issued semantic scopes to canonical source instances. It retains
this coverage object and its exact candidate/selection custody; it does not
choose a capability or admit backend evidence.
