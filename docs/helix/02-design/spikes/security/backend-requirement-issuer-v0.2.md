## Complete demand instances

Current RequiredPremise0.1 matches all original contracts/atoms globally, but
its alternative search asks for any semantic atom per source/scope/origin.
This establishes source-complete correspondence. It does not establish complete
coverage of multiple independent kinds for one source.

For example, one actual field source can require exact codec and privacy duties.
Codec at capability A and privacy at B may satisfy every globally selected
obligation while neither alternative alone discharges both duties. Merely adding
kind labels to a profile without changing the matcher would incorrectly leave
A and B looking source-complete.

Introduce separately versioned required-obligations0.2 with an independently
issued instance inventory:

`DemandInstance = (canonical source, actual scope, required kind, occurrence)`.

For each instance, retain the exact eligible original capability and complete
required template expansion: original contracts, all typed atoms/cases/sites and
prerequisites. Compare every selected original against the full expected inventory
first; choosing one alternative never drops another selected obligation. Then
require `forall actual scope, exists eligible capability, forall required demand
instances of that scope: its complete expansion is matched`. No per-instance
fragment union, no source-only presence test, and no global capability intersection.

Inventory construction must account for every actual source/scope edge plus
every applicable kind/occurrence. Projection equality alone cannot prove kind
completeness; the typed owner issuer and independent template rules must do so.
Avoid duplicate-kind collapse or reusing one original obligation as several
unproved independent duties. The initial profile uses distinct original template
instances; a shared enforcement composite requires an explicit separate contract.
Preserve all shared original-ID capability origins when a template intentionally
shares the identical original declaration across capabilities.

Required-obligations0.1 must not silently gain kind semantics. Keep its existing
source-level experiment qualified or refuse it at the new kind matcher boundary.
Actual decoder admission-obligation0.2 subjects remain paired; do not confuse
that parameter version with this separately versioned requirement inventory.
