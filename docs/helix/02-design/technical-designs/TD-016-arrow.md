# TD-016: Arrow schema authority and native validation boundary

Core NativeJson owns the schema source. The integration grammar and extension manifest
are generated by scripts/arrow-schema.ts; semantic checks live in the adapter. A temporary
JSON.parse view validates known shape fields, while exports, edits and getters always
operate on the original tagged tree. Duplicate metadata is never converted into a Map.

Exact integer checks read original tokens, remove decimal scale only when the removed
digits are zero, cap the magnitude before allocating exponent padding, and compare
signed dictionary bounds with bigint. This permits exact scientific integer notation
without accepting fractional IDs that JavaScript would round. Unknown numeric content
is retained without interpretation.

The public module has no Apache Arrow runtime import and remains browser-compatible.
The optional native probe/oracles stay separate and compare behavior before and after
UMF serialization. Future IPC conversion must explicitly handle unknown fields, ordered
metadata, dictionary IDs and native type support instead of trusting native parse success.
No Arrow concept is promoted to core merely because of matching names or storage widths.

Guarded IPC export uses a caller-supplied synchronous backend to decode the supported
JSON schema, encode a schema-only stream and read that actual stream. Core compares both
known native descriptors against the source under explicit defaults/aliases; metadata
arrays and IDs are compared exactly. The backend strips only undefined optional members
from its descriptor JSON view, and core restores the documented semantic defaults.

The backend does not use Arrow's metadata-dropping JSON writer. Descriptor assembly
retains native schema and field metadata, then the guard detects losses introduced by
Map conversion or unsupported content. Byte output is bounded and copied. Before/after
descriptors are trusted backend observations; arbitrary backends may not be treated as
verified codecs just because they assert the expected identity. The bundled optional
backend is the implementation exercised by Bun, Chromium and PyArrow evidence.


IPC capture is separately registered as `umf.arrow.ipc` so schema JSON export cannot
silently collapse a binary archive into an observed schema. The current payload is a
bounded lowercase hex string, avoiding host-specific Buffer dependencies and retaining
all bytes regardless of native support. The one-million-byte limit leaves room within
core serialization bounds; a streaming/external-blob design remains future work.

The optional observation backend reads a copied byte array and returns a bounded JSON
view of the native schema. Its result retains copied source and incomplete status.
Native decoder failure or unsafe host numbers returns uninterpreted status, preserving
the archive. The public capture APIs are in src/adapters/arrow/capture.ts; package files
are generated by scripts/arrow-ipc-schema.ts. They do not import the native runtime.


The logical FlatBuffer vocabulary is generated by scripts/arrow-flatbuffer-schema.ts
from five hashed source files. It records native declaration/member/field inventories
and maps signed long values to bounded canonical decimal strings. A range-pattern
generator avoids rounded JavaScript schema bounds. Union discriminators are paired
with their values in explicit tagged objects; required union members exclude NONE.
The public adapter validates a separate logical package and does not masquerade as an
IPC decoder. Binary field presence, unknown enum values and unknown FlatBuffer offsets
remain source-capture concerns until a wire codec can preserve and interpret them.

Reproduction: `bun scripts/arrow-flatbuffer-schema.ts --check` verifies generated drift;
`bun scripts/arrow-flatbuffer-oracle.ts` compares an independent flatc 23.5.26 inventory.
The latter accepts UMF_FLATC_PATH and UMF_FLATC_LIBRARY_PATH. Local evidence used Ubuntu
arm64 packages flatbuffers-compiler and libflatbuffers23.5.26 version 23.5.26+dfsg-2,
extracted under .cache/flatc without changing system packages. A fresh environment must
supply that compiler; the regular conformance runner checks generated drift but does not
implicitly install or run flatc. Native inventory evidence is recorded separately.


Raw metadata decoding in src/adapters/arrow/flatbuffer-decode.ts uses bounded DataView
reads and inventory-derived layouts, including inline struct alignment and two-slot
unions. Relative offsets must point forward; signed vtable offsets may point either way.
The logical model omits absent fields, avoiding default synthesis. Native unknowns either
produce slot diagnostics or prevent a partial decoded result while source remains intact.
No native Arrow JS runtime is required by this decoder.

Reproduce the native metadata corpus with scripts/arrow-metadata-inputs.py (PyArrow
extraction), scripts/arrow-metadata-authored.py (five optional flatc fixtures),
scripts/arrow-metadata-decode.ts and scripts/arrow-metadata-oracle.py. The flatc scripts
use the pinned compiler/env described above. Extraction preserves already generated,
hash-checked authored fixture entries; ordinary conformance does not require flatc.
Fresh independent re-generation of the authored evidence does require that compiler.
The browser probe also exercises all 70 decoded metadata roots through the public API.
The source format is documented in [FlatBuffers internals](https://flatbuffers.dev/internals/).


The metadata encoder uses the pinned FlatBuffers 25.9.23 Builder through an explicit
optional backend. Shared inventory/layout definitions are in flatbuffer-layout.ts;
core's encoding guard is flatbuffer-encode.ts. The backend prebuilds offsets, writes
inline structs/vectors with declared alignment, and forces defaults for supplied scalar
fields only. Core compares re-decoded output with the pre-backend model to detect both
conversion loss and backend input mutation. Unknown wire omissions are retained in the
model envelope and block standalone logical/binary export.

`bun scripts/arrow-metadata-encode.ts` produces 70 corpus encodings plus two edited/
explicit-default outputs. `.venv/bin/python scripts/arrow-metadata-oracle.py --encoded`
compares all 72 with flatc, retaining Python exact integer decoding. The browser probe
encodes and re-decodes all 70 corpus roots through public APIs. Candidate edits operate
on copies of the logical model; captured source bytes are never implicitly updated.


IPC layout inspection (ipc-layout.ts) reads the source capture once, detects file magic,
locates the footer from the signed little-endian length, and traverses modern/legacy
message prefixes. It invokes the raw metadata decoder and uses exact bodyLength strings
before bounded conversion to offsets. Known message lengths permit traversal even when
unknown table slots have wire-omission markers; their diagnostics and source remain.
Unknown union/enum failures stop traversal because this version cannot safely interpret
the body/header contract. The result intentionally retains partial prior observations.

The layout-result schema is generated by scripts/arrow-ipc-layout-schema.ts. It describes
only the report, not data-body schemas or native semantic validity. PyArrow read_message
supplies independent consumption boundaries; the legacy fixture is generated with
IpcWriteOptions(use_legacy_format=True). Format behavior is grounded in the
[Arrow IPC specification](https://arrow.apache.org/docs/format/Columnar.html).


Footer consistency (ipc-consistency.ts) consumes a fresh layout report and compares
known metadata only when file boundaries are accounted for and no unknown slots exist.
Normalization for comparison supplies native scalar defaults and empty absent vectors;
it never rewrites the captured model. Block matching uses exact offsets, checks type and
extent, and records duplicate/count/order discrepancies. The result schema is generated
by scripts/arrow-ipc-consistency-schema.ts. Mutated-footer tests re-encode actual binary
footers while leaving the embedded stream intact, proving framing success alone cannot
satisfy these checks. The full layout/source remains available with every result.


IPC field rename (ipc-rename.ts) changes only the selected schema Field.name, encodes the
initial metadata with the original prefix style, pads the message to eight bytes, and
copies the remaining messages unchanged. An old-to-new message offset map updates footer
blocks while the footer schema receives the identical rename. Reinspection verifies
framing/footer agreement and exact equality of every copied record/dictionary message.
Candidate construction replaces only the captured byte payload in a copied UMF document.

`bun scripts/arrow-ipc-rename.ts` produces the 19 complete renamed datasets.
`.venv/bin/python scripts/arrow-ipc-rename-oracle.py` reads them with PyArrow and compares
complete expected tables. The browser probe compares its renamed bytes against those
independently checked outputs. The result schema is generated by
scripts/arrow-ipc-rename-schema.ts. Metadata/external name references are not interpreted;
explicit policy and incomplete diagnostics are part of the public transform contract.


Upstream reproduction: scripts/arrow-upstream-fetch.py fetches the full pinned integration
subtree and verifies sizes/Git object hashes before recording SHA-256 provenance.
scripts/arrow-upstream-schemas.py extracts exact-integer schema portions;
arrow-upstream-schemas.ts verifies 91 schema round trips. arrow-upstream.ts checks all
182 binary JSON/YAML round trips, framing/consistency and guarded renames;
arrow-upstream-oracle.py checks native full-table results. The conformance runner includes
these local corpus stages; fetching and browser execution remain explicit operations.

`UMF_CHROMIUM_PATH=/home/erik/.local/bin/chromium bun scripts/arrow-upstream-browser.ts`
repeats the complete binary/schema corpus. It compares successful output bytes with the
native-verified Bun artifacts and asserts matching blocked outcomes. Historical footer
version discrepancies have a focused regression in tests/arrow/upstream.test.ts.
Current reports and per-case diagnostics remain under fixtures/arrow/upstream/; broad
compatibility claims must retain those exclusions.
