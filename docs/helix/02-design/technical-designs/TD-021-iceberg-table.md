# TD-021: Iceberg table metadata preservation

## Scope and Approach

Implement US-021-AC1–4 with a separate table extension over the shared NativeJson tree.
Known-version JSON Schema rules check field shapes; a second walk checks exact integer
widths through definitions, arrays and maps. Embedded schemas reuse CONTRACT-020 validation.
The JS-number view is disposable and never reconstructs source values or checks int64 bounds.
Unknown versions retain source without applying known-version interpretations.

## Components and Interfaces

scripts/iceberg-table-schema.ts generates payload/source/package schemas. The table adapter
composes registry validation with copied pointer access and atomic candidate edits. CONTRACT-021
owns exact fields/APIs. No core vocabulary changes or storage migrations occur. A candidate
coexists with original metadata; rollback means retaining that original document.

## Integration, Security and Performance

Java/Python parsers are independent development-only oracles. Parsing and re-emission are
recorded separately because PyIceberg can read v3 metadata without supporting v3 serialization.
The browser path adds no native runtime dependency. Core input limits remain in force; the
adapter performs no network access, data reads, decryption, expression evaluation or commits.
It offers no throughput guarantee and does not infer reference/transaction validity.

## Tests, Risks and Next Steps

Pinned upstream metadata exercises source shapes, parser defaults and unsupported versions.
Both UMF formats and location candidates are checked; native Java re-emission verifies complete
accepted model equality after changing only location. Tests cover exact counter limits and
mutation isolation; Chromium repeats outcomes. Native normalization and incomplete reference
semantics remain explicit risks. Next broaden table reference/history consistency, partition/sort
compatibility and dependency-aware schema evolution, then physical and cross-system evidence.


AC4 uses a separate linear pass over retained identities. Canonical BigInt keys avoid rounded
snapshot equality; duplicate keys become unresolved. Resolution records source pointers, with
legacy target pointers representing existing source rather than inserted defaults. Neither the
payload nor its native shape validator changes. The report has a standalone JSON Schema and
always declares complete:false. Snapshot parents and historical schemas are not resolved
against an incomplete retained/current-only universe. Bun and Chromium verify report parity.


AC5 introduces a pure browser-safe transform type inspector, independently reusable by future
partition and sort binding. Source strings remain unchanged; temporary decimal/fixed/parameter
parsing uses bounded BigInt values. Its standalone report schema distinguishes incompatibility
from unavailable interpretation. The Java oracle constructs native types and asks native
transform implementations, rather than reimplementing the TS matrix. The specification/native
day result distinction is checked explicitly. Next bind this inspector to selected table fields
and retain unresolved historical/multi-source context rather than guessing.


AC6 builds a copied index of current schema fields with struct pointers and collection ancestry,
then binds only selected partition/sort fields. The standalone AC5 inspector supplies type
assessments. Context errors block interpretation while import/export stays authoritative.
A report schema embeds AC5's assessment schema; its generator is
scripts/iceberg-transform-binding-schema.ts. Source schema generation now enforces v1/v2
single-source versus v3 exclusive single/multi-source shape and v2/v3 partition field IDs.
The authored nested and multi-source fixtures exercise independent Java parsing/re-emission;
Java's multi-source source-id error remains evidence, not a reason to discard source-ids.


AC7 copies the current schema tree, locates a named field by ID through struct/list/map shapes,
checks sibling conflicts, appends the schema with the caller's unused ID and updates the current
selection. It reuses exact source rendering, candidate validation and AC6 binding inspection.
Original trees and unrelated fields remain untouched. The Java oracle lives in the Iceberg
package solely to access the pinned package-private SchemaUpdate constructor; it is development
code, never a browser dependency. Native metadata comparison excludes only commit update time.
The report schema is generated by scripts/iceberg-rename-schema.ts. Unknown name dependencies,
version migration, history deduplication and safe commit behavior remain explicit limitations.


AC8 adds primitive widening candidates using the same exact-tree version-append approach.
It traverses current named fields, rejects nested map-key changes, bounds target syntax and
checks the pinned three widening families. All retained partition specs are scanned for
source-ID dependencies before producing a candidate. Unknown dependent transforms block;
known transform checks reuse AC5. History remains authoritative for original bounds encodings.
The native oracle calls SchemaUpdate.updateColumn rather than comparing a second copy of the
TS rules. Generated report schema, six native fixtures and browser parity qualify this scope.
V3 date/unknown promotions, default execution and physical reader behavior remain next work.


AC9 connects AC8 candidates to native physical data reads. A pinned PyArrow writer assigns
field IDs while deliberately changing physical column names. Java GenericParquetReaders projects
those files under original and promoted schemas, checks expected exact values/runtime types and
untouched columns, and records data/metadata hashes. The Bun evidence test binds those hashes to
newly generated public candidates. All IO is to explicitly authored local fixture paths; there
is no table location fetch, catalog service, data rewrite or public Java dependency. JVM data
reader dependencies live only in the native oracle POM. Full scan planning and bounds behavior
remain separate work.
