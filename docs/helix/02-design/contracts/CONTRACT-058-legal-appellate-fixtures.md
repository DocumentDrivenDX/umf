# CONTRACT-058: Legal appellate fixed fixtures

**Version:** 1.0.0. **Owner:** UMF source/schema maintainers.

## Purpose

Define portable historical judicial documents and fixed temporal workflow fixtures
for US-061-AC9–AC12. CONTRACT-052 governs the enclosing pack and source export.

## Scope and boundaries

Source PDFs, authored native TableSpec schemas and UTF-8 CSV rows are local inputs.
Inspecting the pack MUST NOT trigger collection, prompt execution, email or PACER
(Public Access to Court Electronic Records) access. CONTRACT-053 component scaling
MUST NOT be interpreted as implementing temporal workflow state transitions.

## Normative surface

`spec/domain-packs/legal-appellate/umf/*.json` governs exact column names, native
types, nullability, primary keys and foreign keys. CSV uses headers, `\N` for
null, standard double-quote escaping and LF records. Empty text remains distinct.

| Table | Meaning and required preservation |
| --- | --- |
| courts | Native court identity, name, level, jurisdiction and listing URL; state highest courts MUST be explicit. |
| cases | Source-scoped case identity, case name, docket spelling and court identity. Consolidated dockets MUST retain original spelling. |
| decisions | Content-version identity, case, kind, date when known, source URL, local original path, SHA-256, page count and bounded historical status. |
| decision_pages | One-based PDF ordinal, exact extracted text and extraction status; MUST NOT claim native page/line fidelity. |
| issue_groups | Curated issue, legal basis, comparison scope and assessment qualification. Shared group membership MUST NOT imply an actual conflict. |
| decision_groups | Document/group associations with role and factual/statutory distinction. |
| annotations | Attributed provisional screening candidate, disputed issue, outcome effect, opinion voice, method, review state and historical qualification. |
| annotation_evidence | Annotation/document/page links with exact extracted excerpts. Evidence MUST resolve to retained page text; excerpts MUST NOT imply endorsement by the court. |
| counsel | Counsel name, represented party scope, source document/page, as-of spelling and observation status. Unknown counsel MUST remain unknown. |
| collection_windows | Fabricated expected source/window identities and bounded dates; source-window coverage is separate from known document processing. |
| workflow_events | Ordered fabricated events with recipient, document, prompt version, alert kind, stage, outcome and retry identity where applicable. |
| expected_outputs | Independently authored per-event expectations: action, notification identity, open failure count and detail. MUST NOT be generated by the transition implementation under test. |
| enrichment_fixtures | Entirely fictional party/counsel lookup examples with explicit fabricated origin; MUST NOT assert counsel representation in a real case. |
| fictional_reviews | Fictional review identities for typed enrichment lookup association; case/party MUST agree with the linked lookup. |

Every table has an explicit row source binding. Observed metadata, extracted text,
curated annotations and fabricated workflow rows MUST have separate source descriptors.
All local source bytes MUST be hash pinned. Every original MUST retain source URL,
retrieval timestamp and rights basis. Original document bytes are authoritative.

Fixture policy: a successful receipt deduplicates recipient + PDF hash + alert kind;
a failed delivery MUST leave retry eligible. Prompt changes permit re-screening but
alone MUST NOT generate a second email. Amended content permits a new decision
alert; vacatur permits a status alert. Counsel enrichment updates the existing review
item. Successful-empty collection MUST NOT be equated with a failed listing.
Delivery-request events contain a proposed simulated transport outcome applied
only after eligibility; suppression MUST NOT create a receipt. Vacatur follows
the typed `vacates` decision link and makes the affected review non-actionable.
Enrichment events reference both fictional review and lookup identities; failed
lookup retains unknown counsel. Expected outputs include affected review state.

The optional loader annotation pins the exact shared document-loader companion
1.0.0 for explicitly invoked finite-inventory acquisition/replay. Its shared
contract governs acquisition, separately from these notification fixtures and the
offline projector. No second downloader is introduced.

## Precedence and compatibility

Pack version 1.0.0, shared extension 1.0.0 and TableSpec schema 1.0 are separate.
Existing legal 1.1.0 remains unchanged. Unknown metadata is retained under
CONTRACT-052; no new core or shared extension semantics are introduced.

## Error semantics

Missing originals, stale hashes, invalid PDFs, duplicate identities, dangling
references and evidence excerpts absent from their page refuse corpus acceptance.
Unknown rights refuse source redistribution. Empty extracted text remains an explicit
page result. Unsupported consumer workflow behavior remains unqualified.

## Examples

A repeated arrival of `castillo` for reviewer A after successful delivery yields
`suppressed_duplicate`; the same content for reviewer B is independently eligible.
A simulated failed listing leaves its expected window unresolved until recovery.

## Non-normative notes

Annotations support development and attorney review. They are not attorney-reviewed
legal ground truth or current treatment research. State statutory distinctions must
be evaluated before inferring a conflict about a shared federal question.
