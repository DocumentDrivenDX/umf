# Legal appellate development pack

Version 1.0.0. A fixed historical corpus for developing the practice's appellate
screening workflow while a more advanced collector is built separately.

Start with `pack.json`, `screening-prompt.md`, and `data/decisions.csv`. The pack
contains **34 original judicial PDFs, 1,689 PDF pages, 27 source-scoped cases,
10 courts and 13 issue groups**. Seven federal circuits, New York's highest court,
Pennsylvania's highest court and selected Supreme Court resolutions are included.
The existing legal operations pack remains separate.

## What you can develop now

Load original PDFs and their page text into a screening/retrieval system. Produce
case name, disputed issue, outcome effect, evidence and party-specific counsel.
Compare candidate decisions across courts, and evaluate against the 18 provisional
annotations. Use `replay.json` to test duplicate receipts, failed delivery/retry,
prompt changes, independent recipients, amendments, vacatur, negative screening,
counsel enrichment and collection/processing failures. Expected outputs are
authored separately from the test interpreter, rather than generated by it.

## Data and provenance

Fifteen native TableSpec schemas have explicit CSV row bindings. Observed
metadata/text, provisional interpretation (`data_kind: unknown`) and fabricated
workflow rows have separate source descriptors. `selection.json` pins each PDF's
URL, download timestamp, SHA-256, date, document kind and historical qualification.
`retrieval-attempts.json` retains actual successful and failed acquisition attempts;
it does not represent complete monitoring coverage. Three unavailable reference
candidates remain metadata-only and are not counted as retained PDFs.

Every page uses a one-based **PDF ordinal**, not a native printed page or line.
pypdf 6.10.0 extracts text without OCR. PDF images, layout, redactions, stamps and
typography remain authoritative in `sources/*.pdf`; extracted text is a convenience.
Original bytes are never rewritten. Three PDFs are judicial mirrors with explicit
publisher qualifications; independent equality with an official-host copy is not
claimed. Per-source rights bases cover judicial opinions/orders under the
[government edicts doctrine](https://www.copyright.gov/comp3/docs/compendium.pdf).
No privately authored briefs, commercial headnotes or exhibits are bundled.

Counsel is **partial**: eight named entries across four documents retain party,
source-page excerpt and as-of date. Other documents remain `not_assessed`; the
Hirschfeld vacatur's text review found no counsel section. No PACER lookup occurred.
The two PACER-like fixtures use entirely fictional cases, parties and counsel.

## Replay policy

Successful receipts deduplicate the tuple `(recipient, PDF SHA-256, alert kind)`.
Failed delivery is eligible for retry. A changed screening prompt permits another
screening pass but does not itself permit a second decision email. Amended bytes
permit a new version review; a vacatur permits a status alert. Enrichment updates
an existing review item. These are explicit development policy choices for review.
No mail is sent, no real recipient is configured, and no production timing is claimed.
Delivery events are requests with proposed simulated transport results; a
suppressed request creates no receipt. Vacatur resolves the affected panel review
through the decision link and marks it non-actionable. Enrichment links fictional
review/lookup identities and checks resulting counsel state, including failure.

Three expected source windows cover successful-empty, recovered listing failure,
and **unattempted** coverage. Thirty events include recovered retrieval,
extraction and screening failures plus two unresolved failures. Preserve expected
windows even when a source produced no events; an event log alone is insufficient.

## Rebuild and verify

With Python and pypdf 6.10.0 installed:

```sh
python scripts/domain-packs/legal-appellate-project.py --check
bun test tests/domain-packs/legal-appellate.test.ts
bun run build
bun scripts/legal-appellate-browser.ts
bun scripts/export-domain-pack.ts --pack spec/domain-packs/legal-appellate/pack.json --output /tmp/legal-appellate-export --include-sources
```

Omit `--check` to regenerate schemas/CSV/manifest from local pinned originals,
curation and replay inputs. Rebuild performs no downloads and refuses changed
originals, duplicate IDs, dangling references and excerpts absent from cited pages.
The export includes exact original PDFs and all fixed inputs.

## Shared acquisition companion

The pack root contains exact shared UMF document-loader companion 1.0.0 bytes, pinned
by `loader-release.json` and the manifest loader annotation. Explicitly invoke
it to acquire the 34-entry `loader-inventory.json`; each entry retains court,
docket, document date/kind, historical scope and the original seed hash as metadata.
Each entry also declares `expected_sha256`, so changed postings refuse this pinned
historical seed. A later refresh inventory can explicitly remove that constraint
to collect new revisions for separate review.

```sh
bun spec/domain-packs/legal-appellate/run.ts --pack spec/domain-packs/legal-appellate/pack.json --inventory spec/domain-packs/legal-appellate/loader-inventory.json --state /tmp/appellate-loader-state --mode backfill --rights redistribute
bun spec/domain-packs/legal-appellate/run.ts --pack spec/domain-packs/legal-appellate/pack.json --state /tmp/appellate-loader-state --mode replay --rights redistribute
```

Use `refresh` for explicit-inventory rechecks. Freeze the exact pack manifest when
reusing state; changed pack bytes require new state. The companion retains
content-addressed originals, revision history, receipts and atomic publications.
It performs no court-site discovery, PDF parsing, screening, email or PACER lookup.
Its separate replay means archive verification, not the fabricated alert replay.
Installing/invoking trusted host code is explicit; inspecting a pack executes none.

To hand selected archived originals to a domain projector, invoke the shared
`read-publication.ts` bridge with a JSON array such as `[{"id":"castillo"}]`.
An optional `revision` selects a specific original-byte SHA-256. The bridge verifies
the committed closure and writes exact objects plus source metadata/rights into a
new directory; it does not modify state or infer legal meaning.

```sh
bun spec/domain-packs/legal-appellate/read-publication.ts --state /tmp/appellate-loader-state --selection /tmp/appellate-selected.json --output /tmp/appellate-projection-input
```

Full historical selection was exercised with all 34 pinned revisions. Its selected
bytes, native dockets and rights agree with this corpus. Retain those contexts when
building an updated projection.

## Limits and next decisions

Annotations are AI-authored, provisional and **not attorney-reviewed ground truth**.
Issue membership alone is not a split: state statutes differ; dissents can dispute
the majority's description; merits disagreement may not change the ultimate result.
Several groups contain Supreme Court resolution or vacatur. Graham and Cobra cite
opposing opinions that are not bundled, so comparison coverage is explicitly partial.
Smith cites a 2024 Chatrie panel; the pinned court URL now serves the 2025 en banc
opinion with a later certiorari stamp. No comprehensive current-treatment check.

To define production loading, obtain the court-site list, designated order types,
the attorney's screening prompt, polling constraints, recipient and alert policy.
Live scheduling, anti-blocking behavior, email attachments/receipts and authenticated
PACER enrichment belong to that consumer workflow. Supreme Court **docket
monitoring remains a separate, undefined workflow**; Supreme Court opinions here
are historical treatment/comparison documents only.


## Python loading and preservation

Install TableSpec 0.0.8 with the pinned dependencies documented in its
[document-loader guide](https://github.com/DocumentDrivenDX/tablespec/blob/main/docs/guide/document-loader.md).
Python executes the admitted inventory contract directly; the bundled Bun runner
is a compatibility reference and is not invoked by TableSpec.

```sh
tablespec document-loader fetch --pack pack.json --inventory loader-inventory.json --output state --rights local-use
tablespec document-loader handoff --state state --output handoff
tablespec document-loader verify-handoff --fetched handoff
tablespec document-loader publish --fetched handoff --backend duckdb --target main.documents --database documents.duckdb --objects originals --mode merge
tablespec document-loader audit --state handoff
```

The handoff is a complete BagIt 1.0 directory with SHA-256 payload and tag
manifests. `preservation.json` maps PREMIS 3 objects, events, agents and inventory
rights; `provenance.jsonld` links acquisition observations and the metadata
projection to exact original revisions using PROV-O. This is a scoped semantic
mapping, not PREMIS XML. Original bytes remain authoritative; text, financial
observations and annotations retain their separately qualified derivations.
Offline publishing performs no source requests. Schedule `audit` to recheck
all retained revisions. Hashes verify fixity, not authenticity or legal rights.
OCFL storage and WARC HTTP capture are optional future adapters.

For Spark, name the exact Unity Catalog table and volume:

```sh
tablespec document-loader publish --fetched handoff --backend spark --target catalog.schema.documents --volume /Volumes/catalog/schema/originals/collection --mode merge
```

SEC acquisition requires `UMF_LOADER_USER_AGENT` with an identifying contact.
The demo inventories are empty until the operator selects sources. Existing
source pins and source-specific redistribution restrictions remain mandatory.
